### 1.0 可复制命令与两个口径（2026-11-25 22:00 补，源自 T30 命令实测）

① 那条命令写在 md 表格里，源码中管道是 `\|\|` 转义态。**从源码直接复制会崩**（实测 rc=2：`unrecognized arguments: || echo ...`）。复制请用下面这段（放在代码块里，源码可直接取用）：

```bash
for f in schema/examples/*.json; do
  python schema/validate_schema.py "$f" --quiet || echo "FAIL $f"
done
```

三个口径要分清：

- `--quiet` 只证「有没有 W」，**不证「W 是什么」**——它把警告码一起吞了。要证「W1 全是 W-fig」需去掉 `--quiet` 单跑那 4 份。
- 4 份 W1 = **B-04 / B-15 / B-17 / B-18**；22:00 逐份去 `--quiet` 复跑，警告码全部为 `[W] W-fig`（必需图缺失），与 ① 的声称一致。
- ③ 的 `ls 验证器/l3*` 是**反证类命令**，rc=2 才是通过；别把它读成"跑挂了"。

## 二、18 处 fail 的归因（三类，性质完全不同）

| 类别 | 处数 | 题号 | 性质 | 该谁修 |
|---|---|---|---|---|
| **A. 验证器缺陷** | **9** | A-04×2、A-08、A-09、B-01、B-03×2、B-04、B-12 | **假阳性**：方程代入前序值后变成 `0=0`，`sympy.solve(0, x)` 返回 `[]`，被当成「无解→自相矛盾」 | 验证器（1 行判断） |
| **B. `k` 同名异义** | **6** | B-10×4、B-19×2 | **真冲突**：同一个 `k` 在不同题里含义不同，白名单只收 2 种 | 白名单/口径 |
| **C. 合步表示** | **3** | B-20×3 | **真缺陷**：把 2–3 条独立方程/结果**相加**存进一个 `sympy` 串，量纲当然不一致 | 金标数据 |

### 2.1 A 类：9 处是验证器自己判错（不是金标错）

9 处 fail 的 detail **逐字相同**：

```
per_step：本步方程对本步符号无解（方程自相矛盾）｜chain：全题联立残差 0（chain）（两模式不一致，按 fail 报，需人工复核）
```

`chain` 说残差 0（全题相容），`per_step` 说无解。查代码 `验证器/l1_deduce.py:329-347`：

```python
e = _subs(expr, prior)                      # 把前序步骤的 value 代进去
sols = sympy.solve(e, Symbol(sym))
...
if isinstance(sols, list) and not sols:
    return Verdict("fail", "本步方程对本步符号无解（方程自相矛盾）", "E-10", "per_step")
```

我直接验证了 sympy 的行为：

```
solve(v1 - 20, v1)  = [20]
solve(0, v1)        = []     ← 空列表
solve(20-20, v1)    = []
```

问题就出在这里：**这 9 步的方程，代入前序值后恒等于 0**（因为它们的符号在前面已经赋过值），`sympy.solve(0, x)` 返回 `[]`，代码把「方程恒成立」读成了「方程无解」。

这 9 步的实际内容（我逐条查的）：

| 步 | kind | sympy | 说明 |
|---|---|---|---|
| A-04-S02 | discussion | `v1 - 20` | v1 在 S01 已赋 20 |
| A-04-S06 | discussion | `x - 680` | x 在 S04 已赋 680 |
| A-08-S09 | equation | `dt - (v2b + v0)/a2` | 结果复述 |
| A-09-S06 | discussion | `x - 4` | 结果复述 |
| B-01-S06 | discussion | `x - 2401/800` | 结果复述 |
| B-03-S03 | discussion | `v - 4` | 结果复述 |
| B-03-S06 | discussion | `s2 - 27/10` | 结果复述 |
| B-04-S07 | discussion | `W + 4200` | 结果复述 |
| B-12-S06 | value | `v1 - 8` | 结果复述 |

**7 处是 `discussion`（复述结论）、1 处是 `equation`（A-08-S09 `dt - (v2b + v0)/a2`）、1 处是 `value`（B-12-S06 写结果），全部是合法步。** 不是金标错。

> **更正（2026-11-25 22:00）**：此处原写「8 处 discussion、1 处 value」，与上面那张表自己标的 `A-08-S09 = equation` 矛盾。逐份读 `schema/examples/*.json` 的 `kind` 字段复算：7 discussion + 1 equation + 1 value，总数 9 不变，只是分格错了一格。**结论不受影响**（9 步全是合法步）。

我把这 9 步的**代入后残差**逐条算了出来（调 `l1_deduce` 自己的 `collect_knowns` / `prepare` / `_subs`）：

| 步 | 代入后 e | 是否恒 0 |
|---|---|---|
| A-04-S02 / A-04-S06 / A-09-S06 / B-01-S06 / B-03-S03 / B-03-S06 / B-04-S07 / B-12-S06 | **0** | ✅ |
| A-08-S09 | **−5.55e-17** | 数值上是 0，但 `_is_zero` 返回 False（浮点残留） |

**9/9 全部是恒等式**，没有一处是真矛盾。

> **修的时候注意**：不能写成 `if e == 0`。A-08-S09 的残差是 `−5.55e-17`，精确比较会漏掉它，得用 `abs(float(e)) < 1e-9` 这类容差。这一条不写清，修完会剩 1 处 fail，然后被误当成「金标还有问题」。

这类步在 27 份里很常见（`discussion` 共 40 步），所以只修数据不改代码是修不完的——**必须改验证器**。

### 2.2 B 类：`k` 在 5 道题里有 5 种含义，白名单只收 2 种

白名单里 `k` 有两条，本来就是同名异义：

| 规范写法 | 含义 | 量纲 | 首现 |
|---|---|---|---|
| `k` | 弹簧劲度系数 | `[mass]/[time]²` | A-02 |
| `k` | 开普勒常量（GM/4π²） | `[length]³/[time]²` | A-10 |

但实际用到的还有三种：

| 题 | `k` 的用法 | 实际量纲 | 验证器报的错 |
|---|---|---|---|
| B-10 | `k*(m1+m2)*g`，且 S05 写 `k=1/10` | **无量纲**（阻力系数） | 「值单位 1 的量纲 dimensionless 与白名单 `[mass]/[time]²` 不符」 |
| B-19 | `k = h1/h2`（高度比） | **无量纲** | 「`k` 为 kg/s²，`-h0/h` 为无量纲」 |
| B-20 | `k1 = 1/(M+m)` | **1/质量** | 参与合步那一串（见 C 类） |

**这正是 T20 裁定书里被降级掉的那条能力要求。** 交接卡当时写的是「第 3 条『同名异义消歧』已由裁定书自行降级（无实例）」。现在有实例了，而且是 **6 处 fail**。

顺带一提：这类冲突**不会**因为改数据就消失——`k` 是高中物理最常用的符号之一，只要白名单是「一个符号一个量纲」的全局表，这类冲突会持续出现。要么白名单支持「按题号作用域」，要么强制改名（`k_spring` / `k_kepler` / `kappa`）。

### 2.3 C 类：B-20 有三步把多条方程加在一起存

| 步 | `sympy` 实际内容 | 问题 |
|---|---|---|
| B-20-S05 | `(k1*(M+m) - 1) + (k2*M - 1) + (b2*M + mu*m*g)` | **三条独立方程相加** |
| B-20-S06 | `(M - 1) + (m - 1) + (mu - 1/5)` | **三个独立结果相加** |
| B-20-S10 | `(L - 9/2) + (t - 3/2)` | **两个独立结果相加** |

L2 报「加减项量纲不一致：`M` 为 kg；`mu` 为无量纲」——**报得对**。把质量、无量纲、长度相加本来就不成立。这不是 L2 严格，是数据表示错了。

这与 G1 打勾稿里登记的 `A-05-S10`「一步含动量守恒与能量守恒两式（合步）」是**同一个问题的两面**：G1 把合步登记为「已知缺陷，新增题不得照抄」，但 **B-20 有三步就是合步**，而且 L2 处理不了。两条口径没对齐。

### 2.4 另有 41 处「数据错误」是误报，不是缺陷

实跑输出里每份都有若干条：

```
数据错误（不静默修，已跳过）：
  - A-06-S01 [L1] per_step：data_error(empty): sympy 串为空｜…
```

我数了全表：**空 `sympy` 的步共 41 处，全部是 `judgment`(35) + `critical`(6)，且 41 处全部有 `criterion`**（`空 sympy 但无 criterion` = 0）。

按 Schema R15，`judgment`/`critical` 要求有 `criterion`、`equation` 必 null——**这 41 处完全合法**。把它们叫「数据错误」会让任何读报告的人以为数据烂了。这是**术语问题**，改个措辞即可（建议叫「无方程步，跳过」）。

## 四、三条路，我的建议

| 选项 | 内容 | 代价 | 收益 |
|---|---|---|---|
| **A（推荐）先修再跑** | ① 修 `solve(0,x)` 空解判断（1 处代码）；② `k` 消歧（白名单加作用域或强制改名）；③ B-20 三步拆开；④ L4 接入主链路；⑤ 27 题重跑出具报告 | 全是修，无新能力；①②③④都在现有代码内 | 修完 G3 的 ③④ 可一次成立（L3 另说） |
| **B 改闸门措辞** | 把 G3 的「L1–L4」改为「L1/L2 全自动层可跑 + L4 接入主链路」，L3 按 Schema 自己的标注（**半自动**）列为观察项，不作闸 | 只有你能改 | 让闸门与 Schema 的分层对齐，消除一个当前不可能达成的条件 |
| **C 缩范围** | G3 只认「T20 那 7 题端到端 + 27 份金标结构合规」，不要求验证器全过 | 最快 | 但等于把「验证器能验金标」这件事推迟到 G4，风险后移 |

**我的建议：A 的 ①②③④ + B 的措辞。**

- ①②③④ 是**修**不是**建**：`solve` 空解是 1 行判断；`k` 消歧可以先用「改名」最省事（B-10/B-19/B-20 里把 `k` 改成 `kappa`/`k_ratio`/`k_mass`）；B-20 三步拆开只是把相加的三项分成三条 check；L4 按 `runner` 注释「不碰」，是把 `l4_condition.main()` 挂进去。**没有一件需要新能力。**
- **L3 建议走 B，理由不是「做不了」，而是「它本来就不该是闸门条件」**：Schema 自己把 L3 标成**半自动**、L5「仅人工」、L6「仅辅助」。拿一个半自动层去当「可跑」的硬条件，等于要求机器完成一件它自己声明只做一半的事。要写也行（参数代 0/∞ 看是否出荒谬值），但那是**新增设计**，不是修 bug，别混进这一轮。
- 提醒一句：**L3 与视觉无关**（见 §1.1 的术语纠正）。所以「等 T12b」这个理由不成立，不能用它来解释 L3 为什么没做。
