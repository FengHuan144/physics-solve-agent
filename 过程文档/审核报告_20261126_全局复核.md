## 2. P0 — 最重要的一条：主指标现在没有分母，也没有区分度

### 2.1 两个数必须一起看

| 口径 | 数 | 含义 | 能不能对外 |
|---|---|---|---|
| 按全分算 | **96 / 260 = 36.9%** | 把 164 分 `na` 当成 0 分 | ❌ 低估，na 不是错 |
| 按可判分算 | **96 / 96 = 100%** | 只算能判的 96 分 | ❌ 高估，见 2.2 |

可判分占比：**96 / 260 = 36.9%**（点级 67/170 = 39.4%，两数一致）。即 **63% 的分值当前判不了**。

### 2.2 为什么「100%」是假的

读 `判分器/grader.py:251-260`，`credit` 只有三条出口：

1. 归属为空 / 槽位碰撞 → `na`
2. **任一步 fail → miss**
3. 全步 pass 或与金标同式（eqsim ≥ 0.9）→ `hit`

`miss` 只在 L1/L2 报 `fail` 时产生，而 L1 判的是「本步方程与本题取值是否自洽」，**不判建模是否用了正确题给条件**。所以「错但自洽」一律 `hit`。

实测后果：20 题 **0 miss**。而人工盲判已确认其中 **4 个 hit 是错的**（`A-09-S02/S03/S09`、`B-04-S04`，合计 **5 分**），另有 **2 个归属不足**（`A-10-S04`、`B-01-S02`，合计 2 分）。

| 口径 | 数 |
|---|---|
| 机器账面（可判分内） | 96 / 96 = 100% |
| 扣已知假 hit（5 分） | ≤ 91 / 96 = **94.8%** |
| 再扣归属不足（2 分） | ≤ 89 / 96 = **92.7%** |
| 覆盖 | 96 / 260 = **36.9%** |

**结论**：G5 要的「分值加权得分率」，现在**既没有完整分母（63% 判不了），也没有区分度（判得了的全对）**。这不是 bug，是 `原始资料/agent.md` §7 第一条「建模错误无法自动验证」的量化后果 —— 项目早就写明了这条边界，只是今天第一次量到它有多大。

### 2.3 一个容易混的陷阱：R3 87.1% ≠ 能判 87%

- R3 **148/170 = 87.1%**：`by` 里至少一步**有式子**（可复核）。
- 可判率 **67/170 = 39.4%**：真的能给出 hit/miss。

差的那 81 个点，是「有式子但欠定/算不出」。**87.1% 听起来接近满分，实际可判不到四成。** 两个数以后不许互相替代引用。

### 2.4 79% 的 hit 没经过「与金标同式」这一关

复算 67 个 hit 的判据来源（`判分器/out` 的 `basis` 字段）：

| 判据 | 条数 | 含义 |
|---|---:|---|
| 与金标同式（eqsim = 1.0） | **14** | 真的对上了金标那条式子 |
| **L1/L2 全 pass** | **53（79%）** | 只证明「本步自洽」，**没比对金标** |

再对那 53 条算「承载步方程 vs 金标方程的相似度」：≥0.9 的 **14** 条、<0.5 的 **36** 条、另 **3** 条 `best=None`（没有可比对象）。

这 36 条不等于 36 个错——符号改名会让相似度天然偏低（金标过别名层：`A-04` 改写 **0**、`A-09` 改写 **0**、`A-08` 改写 4，答案用 `v`、金标用 `v1`，相似度必然低）。**但它说明这个判据与"对不对"基本无关**：既漏（A-09-S02 全 pass 而建模错），也会误杀（符号不同而式子等价）。

所以「加一条同式门槛」补不上：门槛紧了误杀真 hit，门槛松了等于没加。并行线（`临时/t36/hit_basis.py`）另算了「18 条确实同式 / 8 条只差常数 / 24 条真不同式」，**这三个数我未独立复算**，但方向与我的相似度分布一致。
