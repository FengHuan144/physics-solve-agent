# 单题解析 · 原型

双击 `单题解析.html` 就能用。单文件、零外部依赖、断网可开。
一道题一页：左边题干原图和已知量，右边分步解析 —— **每一步在算什么、值几分、为什么这么给分、学生常错在哪**。

## 要「点一下就能算」：`app.py`

在项目根目录跑（不是 `原型/` 里）：

```bash
python app.py                # http://127.0.0.1:8765   演示模式，不调 API
python app.py --live         # 额外打开实时开关（还需 DEEPSEEK_API_KEY，会花钱）
python app.py --port 8791    # 换端口
```

打开是一个题库页：20 行，每行一个「跑一遍」。点下去走四步，约 30 秒，出单题解析页——
和 `模型解析_20题.html` 同一套渲染，只是只装这一题。

| 模式 | 第 1 步「解题」 | 第 2、3 步 |
|---|---|---|
| 演示（默认） | 复用 `评测/T20/out/{qid}.json`，**不调 API** | **真跑** |
| 实时（`--live`） | 调 deepseek-flash，实测 1–2.5 分钟、约 0.08–0.14 元 | **真跑** |

两个模式**只差第 1 步**。所以「演示」不是假跑，是跳过最贵的那一步；校验器和判分器每次都是真执行。
页面顶部有一条灰条写明这次是哪一种，不会让演示结果冒充实时结果。

**边界**：只支持题库内 20 题。上传任意新题要另开一路——`run_solve.solve()` 依赖
`schema/examples/{qid}.json` 金标做字段转换，新题没有金标。这一版没做。

产物在 `临时/app/<job_id>/`：`{qid}.json` / `{qid}_validated.json` / `{qid}_grade.json` / `result.html`。
`result.html` 自包含（题图已转 base64），可以单独拷走。

验收：`python 原型/_selftest_服务.py --base http://127.0.0.1:8765`（17 条，需 playwright + 本机 Chrome）

实时链路已实测一次：B-20，**153 s / 0.14 元 / 13 步 / 2 hit · 8 na**。na 的成因与三个可选方向见 `子agent/T37_实时首跑_实测与发现.agent.md`。

模型版顶部有一条黄色横幅，写明三件事：不是标准答案、L1/L2 只验自洽不验建模对错、「pass」不等于「这一步对」。
顶栏写「判了 6/9 点 ｜ 9/14 分」，分数是小字——**na 是判不了，不是判错**。
20 题里 9 道 na ≥70%，B-02 更是 6 个采分点全部判不了。不看清这一点会把 0/9 误读成「模型全错」。

采分点明细默认折叠，点开能看到每一点：编号、承载步、状态、分值、一句人话原因。
`na` 的原因分几类：给分要求对不上、条件不够要联立、符号不认识——不是「模型做错了」。

## 先划清它是什么

| | 是 | 不是 |
|---|---|---|
| 功能 | 把一份结构化答案 JSON 排成能读的一页 | 不会自己解题，也不批改谁写的解 |
| 用户 | 老师看每步的给分依据；学生看每步怎么推 | 不是多题队列、不是审批后台 |
| 数据 | 现成的 `schema/examples/*.json`（7 道，全部金标） | 没有任何模型输出，也没有学生作答 |

这一页是**渲染层**。真正的产品是那份 step 级 JSON —— 谁产出的 JSON 好，这一页就好看；JSON 里没写的，这一页也编不出来。

## 页面上的每一块，数据从哪来

| 页面位置 | JSON 字段 | 备注 |
|---|---|---|
| 顶栏 `B-20 · 2024 山东卷 第17题` | `meta.answer_id / source / question_no` | 原值 |
| 顶栏 `14/14 分` | `grading.score_awarded / score_total` | 原值，不重算 |
| 图例条 `L1 通过 x/y 步` | 步骤级 `checks[]` 统计 | 2026-11-26 改版：整题层 `layers` 有 15/20 题是 `na`，没信息量，改按步骤统计 |
| 采分点明细 | `grading.points[]` | 点级三态 + 承载步 + 人话原因 |
| 左栏题干 | `question.stem_text` | 原文照录 |
| 左栏图 + 图题 | `question.figures[]` + `原始资料/题图/<题号>_图<N>.png` | 图文件按名扫，缺就出灰框 |
| 左栏「已知」 | `situation.given[]` | `source=figure` 的加「图上读出」角标 |
| 左栏「小问」 | `question.subquestions[]` | 带分值 |
| 「整题思路」 | `outline[].title / depends_on` | 依赖关系写成「接第 N 步」 |
| 每步标题 + 步型 | `steps[].title / kind` | 方程步／结果步／判断步／临界步／讨论步 |
| 每步分值 | `grading.point_hits[].score_possible` | 逐步取值，不是平摊 |
| 定律标签 | `steps[].law_ids` → `知识表/定律适用条件_v1.csv` | 悬停出「一句话表述 + 典型误用」 |
| 叙述 | `steps[].statement` | 原文照录 |
| 式子 | `steps[].equation.sympy` | 美化是显示层，悬停看 `raw:` 原值 |
| 结果 | `steps[].value` | `number` 为 null 时退回 `exact` 并标「符号解」 |
| 「判据」框 | `steps[].criterion.text` | 与叙述重复度 ≥60% 就不显示 |
| 「容易错在」框 | `steps[].checks[]` 里 `layer=L4` 的 `detail` | **原文照录，不改写**；与叙述重复的跳过 |
| 「校验 L1✓ L2✓」折叠行 | `steps[].checks[]` 的 L1/L2 | L4 已提炼到上面，这里不重复 |

## 几条有意的取舍（免得被当成 bug）

- **不显示扣分。** 顶栏是 JSON 自带的 `score_awarded`，不是按什么规则算的。
- **「容易错在」是原话，不是我写的。** 它来自金标答案里审核用的 L4 说明（例如「漏重力项会得 v＝√(3gR)」）。原文没写的题就没有这一框 —— 不补。
- **重复的内容会消失。** 叙述、判据、L4 说明三者常常在说同一件事，按 2-gram 包含度判重（阈值 0.6），只留信息量最大的两处。
- **结果步的式子会合并。** `equation: v-4` 与 `value: 4.0 m/s` 是同一句话，只显示 `⇒ v = 4.0 m/s`，避免把 JSON 里 4 / 4.0 的写法差异摆到读者眼前。
- **数字按 JSON 原文保留**（`parse_float=str`），`6.0` 不会变成 `6`。
- **式子美化是纯显示层**：`Rational(1,2)`→`(1/2)`、`**2`→`²`、单字母相乘省点（`m·g`→`mg`）。美化不了的形态（`sqrt(...)`、`Piecewise`）原样显示，不猜。

## 2026-11-26 改版：七处产品缺陷修复

用户在页面上实际会撞到的七个问题，逐条改掉。改的都是**呈现与数据对齐**，判分逻辑一行没动。

| # | 原来 | 现在 |
|---|---|---|
| 1 | 顶栏「9/14 分」大号红字，读成「模型只对六成」 | 主位改「判了 6/9 点」，分数降为小字 |
| 2 | A-09 第 05 步打红叉，但采分点判命中给 2 分 | 验证器补 `--alias`，与判分器同源；20 题 160 个状态变化，红叉消失 |
| 3 | `T`（绳张力）被白名单当周期，L2 报「量纲应为秒」 | 同 2：符号先归一 `T→FT` 再判；另有 2 条由 alias **暴露出真错**（`m*sqrt(v)`） |
| 4 | `⇒v = 9.486832980505138 m/s`（15 位小数） | 3 位有效数字，原值挂 `title` 可核对 |
| 5 | A-02 顶栏 20 分，明细只凑得 18 分 | `by` 为空的点不再丢弃，页脚写明「另 1 个点合计 2 分没有对应步骤」 |
| 6 | `L1 L2 ✓ ✗ ·` 一页四种符号，零解释 | 图例条：动态统计 + 每个符号的中文含义 |
| 7 | 只看得到 `6 hit · 3 na`，看不到哪一分丢了为什么 | 采分点明细逐条列出，`na` 翻成人话 |

验收：静态页 11/11、服务端 17/17、验证器 11/11、判分器 7/7。

**没有解决的**：白名单里 `T`/`k`/`P` 这类一词多义符号，仍靠别名表逐题补（不可扩展）；
判分器依然只判「自洽 + 命中采分点」，不判建模对错。这两条属于段 1 的活，不在本次范围。
