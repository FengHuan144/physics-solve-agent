## 3. 产出格式（表 + 三类）

```markdown
| # | 文档:行 | 原话（截 30 字内） | 实测值 | 复跑命令 | 类别 | 建议 |
```

- **A 已闭合**：文档过期，事实已变。建议：在文档尾部追加一行「已闭合」标记（**由 T00 决定改不改，你不改**）。
- **B 仍成立**：真待办。建议：保留，必要时补最新证据位置。
- **C 口径冲突**：两处文档（或同一文档两处）互相矛盾。**必须单列一节**，逐条写「谁和谁冲突、以哪个为准、依据是什么」。C 类不许合并进 A/B。

## 4. 闸

| # | 闸 | 判据 |
|---|---|---|
| ① | 每条有位置 | 必须 `文件:行号`，不许只写「文档里说」 |
| ② | 每条有复跑命令 | 命令要能直接贴进终端；实测值必须是**当场跑出来的** |
| ③ | 三份文档全覆盖 | 每份至少覆盖：闸门表 / 待办清单 / 尾部的「顺序依赖」或「本轮不修」 |
| ④ | C 类单列 | C 类不得混进 A/B，且每条给「以哪个为准」 |
| ⑤ | 零改写 | `git status` 或 md5 证明三份对账对象**一字未动** |

## 5. 不许做的事

1. **不许改任何正文**，包括「顺手把 41 改成 101」。你的产物只有自己的对账文件。
2. **不许引用别的文档当证据**（例如「交接卡说 X，所以 X 成立」）。实测只能是命令输出。
3. **不许对任何闸门打勾**，也不许写「G3 可以过」——只能写「G3 的条件在盘中是否齐备，证据是 X」。
4. **不许把 §16 的更正段算作正文错误**。正文未改是**规则要求**（§1 第 5 条：不改正文，只在卡尾追加），所以要区分「已附更正的过期」与「真没更正」——前者是 A，后者才可能是 C。
5. 不许把「mtime 新」当成「内容对」。mtime 只能证明被写过。
