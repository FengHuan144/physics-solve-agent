## 0. 这个产品要像什么

**像老师改卷，不像 IDE。**

主体是**一张作答纸**：模型的解题过程从上到下写成连续的书写流，不是一张张卡片。
老师拿着红笔在上面打叉、在旁边写批注。

所以：
- 题目是**配角**（可折叠，占左侧一条），作答纸是**主角**（占主视野）
- 可打叉的粒度是**一个式子**，不是「一步」——三步里第二步错了，叉要打在那一个式子上
- 打叉后红叉覆盖在式子上，批注写在旁边，**内联**，不弹窗、不开侧栏抽屉

## 4. 打叉的粒度：一个式子 = 一个可点单元

### 4.1 渲染规则

每个 `step` 渲染成一个「书写块」，块内可能出现 **1–2 个可点单元**：

| 单元 | 内容 | 何时出现 |
|---|---|---|
| `equation` | `step.equation.sympy` 原样显示，等宽字体 | `equation` 非 null |
| `statement` | `step.statement` 文字 | 总能出现（`equation` 为 null 时**它是唯一的可点单元**） |

`value`（结果，如 `v1 = 6.0 m/s`）**也渲染，但不可点** —— 结果是答案，不是推导动作。若结果错了，叉打在产生它的式子上。

### 4.2 点下去发生什么

点任一可点单元 → **内联**展开一个批改槽（就地出现在该单元右侧/下方，不要弹窗、不要侧栏）：

```
┌──────────────────────────────────────────┐
│ m1*g*R = 1/2*m1*v1^2   │ 原因码 [E-11 量纲不统一 ▾]
│                         │ 批注  [________________]
│                         │ [打叉]  [取消]
└──────────────────────────────────────────┘
```

确认后：
- 红叉**覆盖在该单元上**（§5 视觉规范）
- 右侧出现红字：`✗ E-11 ｜ 量纲应为 N`
- 该单元保持可点，再点 → 显示「擦掉」按钮
- 底部计数 +1

### 4.3 记录结构（原型层，注意与 Schema 的差别）

用 `localStorage`，key = `proto:{answer_id}`：

```json
{
  "answer_id": "A-08",
  "marks": [
    {
      "step_id": "A-08-S03",
      "part": "equation",
      "reason_code": "E-11",
      "note": "量纲应为 N",
      "at": "2026-11-25T14:22:01+08:00"
    }
  ]
}
```

> **`part` 字段是原型层的扩展。** Schema 的 `review.rejected_steps[]` 目前只有 `step_id`（步级）。要不要正式加 `part`，属于 Schema 变更，**归 D 路（T08d）或更后的 1.3**。这一路**不许改 Schema**，但要在 `README.md` 里写清「原型记到式级、正式契约目前只到步级，落库时会退化」。

## 5. 红笔视觉规范（无外部资源，全靠 CSS/SVG）

这是「批改式」能不能让人认出来的关键。**必须按下面做，不要自由发挥成现代 UI。**

| 元素 | 规范 |
|---|---|
| 红色 | `#C0392B`（笔迹红，不要用 `#FF0000` 那种屏幕红） |
| 叉号 | 两条 SVG `<path>`，`stroke-width: 2.5`，`stroke-linecap: round`，两端**略超出式子左右各 6px** |
| 手写感 | 叉的旋转角度按 `step_id` 做**确定性哈希**取 **−4°~+4°**（同一个式子刷新后角度不变，不许每次随机） |
| 批注字形 | `font-family: "Kaiti SC","KaiTi","STKaiti","楷体",serif` —— **系统自带楷体，不用外部字体** |
| 批注摆放 | 式子右侧，`rotate(-1.5deg)`，颜色同笔红，字号比正文小 1px |
| 批注框 | 无边框、无背景。就是一个红叉 + 一行红字，别加卡片 |

叉号实现参考（盖在式子容器上）：

```html
<span class="eq-wrap" style="position:relative;display:inline-block">
  <span class="eq">Nf - m1*g = m1*v1^2/R</span>
  <svg style="position:absolute;inset:-6px;pointer-events:none"
       viewBox="0 0 100 40" preserveAspectRatio="none">
    <path d="M4 8 L96 34" stroke="#C0392B" stroke-width="2.5" stroke-linecap="round" fill="none"/>
    <path d="M94 6 L6 36" stroke="#C0392B" stroke-width="2.5" stroke-linecap="round" fill="none"/>
  </svg>
</span>
```

（`preserveAspectRatio="none"` 让叉自动拉满式子宽度；旋转加在外层容器上。）

**式子的显示 —— 这里有个坑，必须先处理：**

`equation.sympy` 存的是**移到一边的表达式**，不是等式。实测：

| JSON 原值 | 直接显示的样子 |
|---|---|
| `m1*g*R - Rational(1,2)*m1*v1**2` | `m1*g*R - Rational(1,2)*m1*v1**2` ← 难看且难懂 |
| `Nf - m1*g - m1*v1**2/R` | 同上 |
| `v2**2 - v1**2 + 2*a1*d` | 同上 |

所以必须写一个 **30 行的纯字符串美化函数**（不许引入 sympy.js，不许 LaTeX）：

| 规则 | 例 |
|---|---|
| `Rational(a,b)` → `a/b` | `Rational(1,2)` → `1/2` |
| `**2` → `²`、`**3` → `³`、`**(1/2)` → `^½` | `v1**2` → `v1²` |
| `*` → 省略（两侧都是字母/括号时用 `·`，字母与数字之间直接连写） | `m1*g*R` → `m1·g·R` |
| 整体是 `A - B` 形式 → 显示成 `A = B` | `Nf - m1*g - m1*v1**2/R` → `Nf = m1·g + m1·v1²/R` |
| 整体是 `A + B` 形式（无负项） → 显示 `A + B = 0` | `v2**2 - v1**2 + 2*a1*d` → `v2² + 2·a1·d = v1²` |

最后一条要小心：**表达式没有唯一正确的等式形式**。所以：

- 美化是**纯显示层**，原值必须能一键看到（鼠标悬停显示 raw，或在式子下方一行 `raw: ...` 小字）
- **不许美化到看不出原值**。老师打叉打的是式子，不是美化结果
- 遇到美化函数处理不了的形态（如嵌套 `sqrt`、`Piecewise`），**原样显示 + 标 `raw`**，不许猜

## 6. 最容易违反的一条：不许显示扣分

批改式天然诱导人做「这里扣 2 分、那里扣 1 分」。**现在做不到，做了就是骗人。**

| 场景 | 允许 | 禁止 |
|---|---|---|
| 已标记处数 | 「已批改 2 处」 | 「已扣 3 分」 |
| 顶部分数 | 直接显示 JSON 的 `score_awarded/score_total`（金标自带） | 用你的批注去重算分数 |
| 交卷 | 「导出批改记录」 | 「提交评分」「生成成绩」 |

理由：**扣分逻辑要等 G4 阈值校准**（AI 稿 vs 老师稿双轨）。现在任何扣分数字都是编的。
