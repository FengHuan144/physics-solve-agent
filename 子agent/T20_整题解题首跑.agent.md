## 3. 草稿格式（模型只输出这个）

字段名故意短，省 token。**必须严格 JSON，不带 markdown 代码块**。

```json
{
  "givens": [
    {"sym": "v0", "val": null, "from": "stem", "note": "题干给的初速度符号"}
  ],
  "sub_results": [
    {"no": "(1)", "result": "Ep_max = 0.6*m*v0**2", "steps": [1, 2, 3, 4, 5]}
  ],
  "steps": [
    {
      "no": 1,
      "title": "从 v-t 图读出 B 的碰前速度",
      "kind": "judgment",
      "stmt": "由图 (b) 纵轴 t=0 处读出，B 碰前速度为 1.2v0，A 静止。",
      "eq": null,
      "value": null,
      "score": 1,
      "point": "读出 1.2v0，且明确说明来自图 (b)"
    },
    {
      "no": 2,
      "title": "碰前到共速的动量守恒",
      "kind": "equation",
      "stmt": "碰前 B 速度 1.2v0、A 静止；t=t0 时两者共速 v0。取碰前速度方向为正。",
      "eq": "m*1.2*v0 - (M+m)*v0",
      "value": null,
      "score": 2,
      "point": "列出动量守恒式，且正确代入共速 v0"
    }
  ]
}
```

### 3.1 硬规则（写进 prompt）

| 字段 | 规则 |
|---|---|
| `kind` | 只能 `equation` / `value` / `judgment` / `discussion`。**`judgment` 的 `eq` 必须 null；`equation` 的 `eq` 必须非 null** |
| `eq` | **sympy 表达式，含义是 `eq = 0`**。不写等号、不写 LaTeX。`3mg = mv²/R` 写成 `3*m*g + m*g - m*v**2/R`。乘法只用 `*`，幂用 `**` |
| `value` | 有定值时 `{"symbol":"v","number":4,"exact":null,"unit":"m/s"}`；纯符号解 `{"symbol":"v","number":null,"exact":"sqrt(2*g*R)","unit":"m/s"}`；否则 null |
| `score` | 本步分值（整数或 0.5 倍数）。同一小问下 `score` 之和**必须等于该问总分** |
| `point` | 一句话说清这一步的采分点是什么 |
| `stmt` | 怎么想的，给人看的话。允许「由图 (b) 读出」 |
| `title` | ≤ 14 字 |
| **`givens`** | **v2 新增**。模型自报它认为题目给了哪些量、哪些是它自己补的。`from` 只能 `stem` / `figure` / `derived` / `invented`。**这是「它有没有偷看图」的唯一证据来源** |

### 3.2 不给模型的信息（给了就是泄题）

金标 `steps[]`、`grading`、`figures[].provides`、**`figures[].caption`**、`situation.given[]`、采分点表、错误码表、符号白名单。

> `caption` 尤其不能给 —— 它是人工写的图题，A-02 的 caption 已把「四个读数在图上」写出来了。**给了整批数据就废了。**

## 4. 转换器映射（**v1 这里有 5 处硬错误，照抄本节**）

| Schema 字段 | 怎么来 |
|---|---|
| `schema_version` | 固定 `"1.2.1"`（v1 卡写 1.2，已过期） |
| `meta.mode` | **`"free"`**。enum 只有 `gold/free/rewrite`，**没有 `"model"`**（v1 卡写错） |
| `meta.model` / `prompt_version` | `"deepseek-flash"` / `"p2"` |
| `question` | 原样抄。**1.2.1 下 `figures[].file` / `file_sha256` 是条件必填，必须连这两个键一起抄**，否则 S0 直接报 |
| `situation.given[]` | 由草稿 `givens` 生成。**不可留空数组**（`minItems: 1`，v1 卡写「留空」是错的） |
| `equation` | `{"latex": to_latex(eq), "sympy": eq, "symbols": syms_of(eq), "parse_status": "ok"}` —— **v1 卡整条漏了**。四项全必填 |
| `criterion`（judgment/critical/discussion） | `{"expr":"True","expected":null,"comparator":"qualitative","text":point[:200]}` —— **v1 卡写 `{"expr":null,"comparator":"label"}`，两处都违约**：`expr` 要求 string 且 minLength 1；`comparator` enum 无 `label` |
| `criterion`（其余步） | **删掉这个键，不要写 null**。Schema 里 criterion 是 `$ref`，值为 null 会被 S0 拦（`None is not of type 'object'`）。R18 检查的是「键缺失或为 null」，所以 pop 掉能正确触发 |
| `steps[].step_id / point_id` | `f"{answer_id}-S{no:02d}"` |
| `steps[].segment_id` | 首跑统一 `"SEG-01"`。分段能力不在本卡范围 |
| `steps[].law_ids` | `[]`。模型不填，不许从金标抄 |
| `steps[].checks` | `[]`，转换后由验证器跑出来再回填 |
| `steps[].confidence` | **常量 `3`**。Schema 要求 integer 1–5、**不可为 null**（v1 卡写 null 是错的）。这是占位，不是模型自评 |
| `steps[].status` | `"draft"` |
| `grading.point_hits` | **`[]` 空**。R6 要求 point_id 必须在采分点表且分值等于金标 —— 模型自报的分值不可能满足 |
| `grading.score_awarded` | **`0`**。R8 要求 Σ point_hits = awarded，空数组配 0 才闭合。**谁给的分必须另行人工核** |
| `validation` | 跑 `验证器/runner.py` 得到 |
| `triage` | 脚本按现有规则生成，不许模型填 |

### 4.1 两个必踩的代码坑

1. **`sympify` 必须显式传 `locals`**。sympy 全局里 `N/Q/S/E/I` 是内建对象，`N - m_a*g` 会 `TypeError`。v1 修前 A-08 有 3 步、B-20 有 1 步被误判「方程为空」。
2. **`to_latex` 不要指望 sympy 默认输出**。`latex` 字段限长 200、只许受限 LaTeX 子集（frac sqrt cdot times sin cos tan le ge approx ^ _ { } 与希腊字母）。超长要截或降级记 issue。

## 5. 模型参数（v1 实测修正）

| 参数 | 值 | 理由 |
|---|---|---|
| `model` | `deepseek-flash` | 唯一收图。**不许 v4-pro** |
| `temperature` | **0.2** | 首跑要可复现。已经知道有 ±6% 步数噪声 |
| `max_tokens` | **按难度分档：易 12k / 中 24k / 难 40k** | v1 卡给死 16000 **不够**：flash 单题推理就吃满、`content` 为空。但也**不许统一抬到 40000** —— 预算是额度不是上限，B-15 从 32768 抬到 65536 后模型直接吐 55,748，支出翻倍答案没变好 |
| 图 | base64 内联 `data:image/png;base64,...` | 不依赖图床 |
| 重试 | **只在 JSON 解析失败时重试 1 次；`finish_reason=length` 直接放弃** | 截断也表现为「解析失败」，按 v1 口径会再烧一轮。**答案错不重试**——挑运气好的那次是作弊 |

**成本结构（实测）**：输出占账单 95%，其中 **84.5% 是思维链**；单题约 0.10 元。`effort` 参数被服务端静默忽略，别指望它省钱。

## 6. 两阶段，闸门不过不进下一阶段

### 阶段 A：单题试水（选最难的一题，不是 B-20）

> v1 选 B-20 是因为「图最全」，但 B-20 恰好是 10 步 14 分、且有 2 个判断步的**中等题**。v2 应选 **A-02**（15 步 20 分，最长、含读图、含多过程）—— 它才是链路的上限压力测试。

通过条件（三条全满足）：

1. 草稿能被 `json.loads` 解析
2. 转换后过 `validate_schema.py`（允许 W，不允许 E）
3. `验证器/runner.py` 至少 L1 或 L2 有**步级**实际结论

> **注意**：整题层 `layers` 一定全是 `na`，这是 R13 聚合口径（有 na 记 na）造成的，**不是判定结果**。判门槛必须按**步级**计数，按整题层字段判会得出「全部无结论」的假结论 —— v1 就在这里差点误判。

### 阶段 B：全 7 题，按有无图分两组

| 组 | 题 | 考什么 |
|---|---|---|
| **带真图** | A-02、B-09、B-20 | 会不会看图 |
| **纯文字** | A-08、A-10、B-02、B-12 | 会不会解题 |

**v1 已证伪**：两组差 4.7 个百分点（95.3% vs 100%），**没有区分力**。这个对照**判不出「记住原题」还是「会做」**，因为两组都近乎全对。报告里**不许**把 100% 写成「模型会做」。

## 7. 判据：硬门槛 + 三观察量 + 三档结论

### 硬门槛（不过就是红）

- 7/7 草稿能 `json.loads`
- 7/7 转换后 Schema 无 E
- ≥5/7 的 L1 或 L2 有**步级**实际结论

### 三个观察量（都出数字，不合并）

| 观察量 | 怎么算 | v1 基线 |
|---|---|---|
| **步数比** | 模型步数 ÷ 金标步数 | **1.53**（中位 1.70，5/7 题 >1.5） |
| **分点命中率** | 人工逐点核 `point` 与金标 `point_hits` 是否等价 | 64.5/66（**必须人工核**，等价写法机器判不了；分母写「金标 N 点」） |
| **图上读数正确率** | 与 `figures[].provides` 比，容差 ±3% | 8/8。±3% 不是放宽，是 B-20 图自身作图误差就有 3%（斜率折合 0.485/0.994，真值 0.5/1.0） |

### 三档结论

| 档 | 条件 |
|---|---|
| **绿** | 分点命中 ≥60% **且** 步数比在 0.7–1.3 **且** 读数全对 |
| **黄** | 命中 30–60%，或步数比越界，或读数部分错 |
| **红** | 命中 <30%，或硬门槛不过 |

**必须写清是「哪一条挂的」。「黄」不带解释等于没结论。**

## 8. 不许做的事（红线）

1. **不许把 `caption` / `provides` / 金标 `steps` 喂给模型。** 调试时顺手贴一段金标，整批数据就废了。
2. **不许手工修 JSON 让它过校验。** 模型输出不合规就记 issue。改了就是掩盖。
3. **不许让模型自评置信度再当结论。** `confidence` 是常量占位。
4. **不许在答案错时重试**，`finish_reason=length` 也不重试。
5. **不许报「准确率 XX%」而不写分母。** 写「分点命中 12/27」不写「44%」。
6. **不许拿金标分值反推模型分值。** 模型分错是最值钱的观察。
7. **余额低于 1 元就停**，402 立即终止整批。
8. **不许把整题层 `layers` 当结论。** 它是聚合值，看步级。
