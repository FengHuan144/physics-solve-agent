## 4. 我抓到回执里的 3 处不准确

### 4.1 T29c §5.4 的根因判断，7 例里只有 3 例成立

它写：「白名单的**常见错误写法**列里其实已经写了这些形式，是扫描只看"在不在白名单"才漏掉的。」

我把 7 个符号的白名单「常见错误写法」列逐格打出来核：

| 符号 | 目标 id | 错误写法列里有吗 |
|---|---|---|
| `T` | FT | ✅ 有（`T（与周期混）`） |
| `alpha` | angA | ✅ 有 |
| `beta` | angB | ✅ 有 |
| **`P`** | F1 | ❌ **没有**（列里只有 `F_1;F甲`） |
| **`Q`** | F2 | ❌ **没有** |
| **`k`** | mu | ❌ **没有**（列里是 `μ动;u;m`） |
| **`k`** | n | ❌ **没有**（列里是 `N`） |

**真实根因不是「错误写法列已登记」，而是这些单字母本身就是白名单里的另一个 id**：`P`＝功率、`Q`＝Qheat 的规范写法（且在 sympy 里是 assumptions 对象）、`k`＝弹簧劲度系数、`T`＝周期。扫描器问的是「在不在白名单」，它们**在**，于是直接被当成那个错的身份用下去，只有量纲能抓。

**这条差别很实际**：按它的说法，修法是「把错误写法列补全」；按真正的机制，修法是「**值单位与该 id 量纲不符的步，强制人工过一遍**」。前者是文档工作，后者是检查项。

### 4.2 T29c §5.4 写「共 5 处」，列了 6 条

`A-09 T→FT`、`B-04 P→F1`、`B-10 R→Rr`、`B-10 k→mu`、`B-16 k→n`、`B-19 k→n` —— **6 条**。若把 `B-04 Q→F2`（reserved）也算，是 7 条。数字与清单不符，属笔误级，但这类「总数句错、表对」正是本项目反复吃亏的形态（G3:116 同型）。

### 4.3 它们没提的一处隐患：B-02 的 `v2` 一槽三值

T29b 只说 `vBx`（−2v）与 `v_B`（+2v）共槽 v2，「两者不在同一式出现，故不撞车」。**但它漏了 given 里的 `vB = 0`**（B 初始静止），也映射到 v2。

所以 B-02 的 `v2` 在题内承载**三个不同的值**：`0`（given）、`−2v`（S05）、`+2v`（S06）。

现在**没有受害者**：B-02 的 L1 全是 `na`（欠定），L1 不把 given 的 0 代进 S05。但 **B-02 就在段 1 那 66 点样本里**（样本 7 题 = B-20 / A-08 / A-02 / B-02 / B-09 / A-10 / B-12）。S2 一旦开始读已知量，就会拿 `v2=0` 去判 S05/S06。

同类但轻一些的还有两处（回执已自报，我确认存在）：`B-20` 的 `v1`（vQ=7 与 v_P=2t 共槽）、`A-03` 的 `v1p`（vm 与 un 共槽）。
