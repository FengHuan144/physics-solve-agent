## 2. 第一批：无争议，立即做

### 2.1 P0-D — 恒等式方程被 L1 判 `pass`

| 项 | 内容 |
|---|---|
| 现象 | `equation.sympy = "0"`（或 `x - x` 等恒等于 0 的式子）→ L1 判 pass，L2 判 na，**同一输入两层打架** |
| 后果 | 上游给一个空方程，L1 认「这一步算对了」，是可绕过的通过 |
| 根因 | `l1_deduce.py` 的 `prepare()` 解析方程后没有「化简为 0」判断；`per_step` / `chain` 都把残差 0 当自洽 |
| 已有可复用件 | `l1_deduce.py:84` 已有 `_is_zero(expr)`；`l2_dimension.py:60` 已有同类判断 |

**修法（指定）**：在 `prepare()` 解析成功后、`per_step` / `chain` 消费前，若 `_is_zero(rec.expr)` 为真，把该步标为 `na`，detail 与 L2 对齐（可用同一句「方程化简为 0，无可比两侧」）。建议走 `rec.skip_kind` 已有的机制，别新造分支——`skip_kind="data_error"` 会输出 `na`，但 detail 会带 `data_error(...)` 前缀，若要对齐 L2 措辞需单独给一个 `skip_kind` 值或特判。**具体实现方式你定，但结果必须是 L1 = `na` 且不是 `skipped`。**

**不许的修法**：把它判 `fail` / `E-10`。空方程不是「算错了」，是「没有判定对象」，按 `schema/字段清单.md` §0 欠定应判 `na`。

### 2.2 说明文档三处（都是「把没说清的说清」，不改行为）

| 位置 | 现状 | 改成 |
|---|---|---|
| `说明.md` §4 | 「数值差 100 倍 → **只有 L1 的残差能抓**」 | **这句是错的**。实测 L1 只读 `value.number` 不读 `value.unit`，L1 也抓不到。改为如实描述：L1 按 number 当 SI 值、L2 只比量纲，两层都不做词头换算（修法见第二批） |
| `说明.md` §8 已知取舍表 | 10 条，无恒等式、无单位换算 | **补第 11、12 条**：恒等式 → na；非 SI 单位的处理方式（按第二批裁定结果填） |
| `说明.md` §8-4 附近 | 承认「只归因单值错，最多 3 次」 | 补一句 **P2**：`chain` 会把上游的错值当成已知前提吸收，于是**根因步判 pass、症状步判 fail**（实测 S03 的 a2 改 3.5，报的是 S04/S08 fail）。别让人以为 fail 的步就是错的步 |

> 说明：`l2_dimension.py` 对 `cm/s^2` 的 detail 写的是「值单位 cm/s^2 与符号 a1 白名单一致」，即 L2 把带词头单位当合规。这比审核报告 §2.2 记的更宽松，写 §4 时按实测写。

## 3. 第二批：**挂起，等口径裁定，不许自己选**

### 3.1 P0-C — 非 SI 单位下 100 倍数值差双层全过

`value.number = 3`、`value.unit = "cm/s^2"` 时，真值是 0.03 m/s²，但：
- `l1_deduce.py:172/243` 是 `v = val.get("number")`，直接把 3 当 SI 值放进 `givens`；
- `l2_dimension.py` 只比量纲，`cm/s²` 与 `m/s²` 同量纲；
- Schema 的 `value.unit` pattern 是 `^[A-Za-z0-9/^*.·-]+$`，`cm/s^2` 合法，拦不住。

### 3.2 三条修法，**由用户裁定**

| 方案 | 做法 | 代价 | 审核方意见 |
|---|---|---|---|
| **1** | L1 读 value 时按 unit 换算为 SI 再入 `givens`（改 `_collect`） | 最正确；要处理 pint 词头、复合单位、题干 given 的单位 | **推荐**：从根上解决，且不改契约 |
| 2 | L2 对「非 SI 基准单位」报 warn/错（`cm/mm/km/g/kJ` 等词头） | 改动小；但 `3 cm/s²` 只被标「单位可疑」，数值仍没被换算 | 次选：让问题至少可见 |
| 3 | Schema 约定「unit 必须 SI 基准」并在 `validate_schema.py` 校验 | 最省事；但要把 74 条公式库与已有 answer 全过一遍 | 不建议：把成本转嫁给上游，且等于改契约 |

**裁定前你可以做的**：把三个方案各自需要改动的文件清单、以及方案 1 的 pint 换算可行性写成一小段评估（不写代码），随第一批一起交。这样裁定下来能立刻动手。

**裁定后统一验收**：`audit_regression.py` 的 C 断言只要求「L1/L2 不许双层全 pass」，不绑定具体方案——三条修法都能让它转绿。
