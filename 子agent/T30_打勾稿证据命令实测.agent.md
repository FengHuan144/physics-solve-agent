## 2. 判定：每条命令归入四类之一

| 类 | 含义 | 处理 |
|---|---|---|
| **甲** | 跑通，**且输出与稿子声称一致** | 记「可复跑」，附输出关键行 |
| **乙** | **跑不通**（文件不在 / 参数不认 / 依赖缺 / 路径错） | 记「假命令」，附 stderr 原文，给出**能跑的等价写法**并实测 |
| **丙** | **能跑，但输出与稿子写的数字不一致** | **最危险的一类**。逐字对比稿子声称 vs 实际输出，差在哪一格写在哪 |
| **丁** | 稿子这项证据是**纯叙述**（如「报告 §2–§5」），没有命令可跑 | 只登记"无命令可复跑"，不评价内容对错 |

**另外单列一张表**：三份稿一共多少条打勾项（G1 有 3 行主表 + 3 项清障；G2 有 3 行；G3 有 ①②③④ 四行），其中**有多少条挂了可复跑命令**。这个比例本身是结论——它说明打勾稿有多可信。

> **不许把「退出码 0」当通过。** 本项目已经 5 次出现「校验器报全过但内容错」。
> 判甲类必须读到输出里的**具体数字**，并和稿子逐个对上。只看到 `exit=0` 就写「通过」的，这张卡判不合格。

## 4. 硬约束（违反任一条即退回）

3. **不许碰 `知识表/别名绑定_v1.csv`。** T29 正在往里加行。
4. **`python 评测/基线/score.py` 跑之前先 `head -40` 看它干什么。** 如果它联网调 API 或要 key，**停下报我，不许擅自跑**（会产生费用）。如果只是读已有产物重新算分，可以跑，但要先确认它把 `scores.csv` 写到哪、会不会覆盖 `评测/基线/` 下已有文件——**覆盖前先备份**。
5. **命令原样跑，不许自己加引号/改参数**。改过就测不出原命令的问题。要测"改后能跑"的版本，另起一行标 `等价写法`。
6. **`grep L3 验证器/*.py` 这类命令的坑**：本项目踩过 `grep` 把 `[OK]` 行里的规则名也算进去导致计数虚高。凡是用 grep 统计条数的，**必须给出完整输出**，不许只给数字。
7. **反证命令（#8 `ls 验证器/l3*`）判法**：`ls` 报 `No such file` 且 `exit≠0` **才是证据成立**（确实没有 L3 文件）。如果 `ls` 因为别的原因失败（路径拼错），不算证据。
