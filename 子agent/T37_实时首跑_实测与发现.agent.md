## 三、na 的成因（本节是重点）

13 步里：pass 3 · na 无方程 2 · **na 符号未知 7** · na 其他 1。

7 步 na 只卡在 **4 个符号**上：

| 符号 | 出现次数 | 含义（本步上下文） | 别名表有无条目 |
|---|---|---|---|
| `v_P` | 6 | P 点物块速度 | **有**（`B-20, v_P → v1`） |
| `F_c` | 4 | P 点轨道对物块的支持力 | 无 |
| `a_8` | 2 | F=8N 时的加速度 | 无 |
| `a_m` | 2 | 物块的加速度 | 无 |

### 推翻一个想当然的修法

「页面 L1 全 na，是不是因为 `验证器.cli` 漏了 `--alias`？」——实测否掉：

```
无 alias：L1 pass 3 / fail 0 / na 10
开 alias：L1 pass 3 / fail 0 / na 10     ← 一个数都没变
```

`v_P → v1` 确实生效了（S09 的式子从 `v_P-a_m*t+V_P-…` 变成 `v1-a_m*t+VP-…`），
但同一步里还有 `a_m` 未知，**整步仍然 na**。

所以：**加 `--alias` 无效，别在这上面花时间。** 真正的瓶颈是 `F_c` / `a_8` / `a_m` 这类
「题目特化的中间量」在白名单里没有槽位——白名单收的是通用物理量（v / a / m / M / F），
模型产出的是带题内下标的派生量。

## 四、这意味着什么

1. **na 高 ≠ 模型解错。** 这次 8 个 na 里，7 个是「认不出符号」，不是「算错」。
   对外说「模型只拿 3/14 分」会严重误导——这句话的字面意思是它做错了，实际是判分器认不全。
2. **补 alias 的收益被高估了。** 只补 `v_P` 不够，因为同一步还有别的未知符号。
   要见到效果，必须一次性补齐该题**所有**中间量，否则 0 收益。
3. **这是覆盖率问题，不是映射规则问题。** 规则（`(qid, symbol) → id`）是对的，缺的是条目。

## 五、三个方向（留白，未选）

| # | 做法 | 代价 | 风险 |
|---|---|---|---|
| 甲 | **按题补全绑定**：每道题把模型可能用的中间量列全，一次补进 `别名绑定_v1.csv` | 20 题 × 约 10 条 = 200 条，机械但有据可查 | 换一道新题又要重来；本质是「为已知产物打补丁」 |
| 乙 | **改判定策略**：一步里未知符号不整步 na，只对「认得的子式」做量纲/代回 | 改 `l1_deduce` / `l2_dimension`，需立卡与回归 | 会把「部分可验」当成「整步可验」，可能制造假 pass |
| 丙 | **改 prompt 约束命名**：要求模型只用白名单符号，中间量必须显式声明 | 改 `prompt_v1.md`，重跑全部 20 题（约 2 元） | 限制模型表达能力，可能掉准确率 |

我的判断（供参考，不替你定）：**乙的风险最高但收益最大**，因为它对任何新题都成立；
甲最安全但不可扩展；丙要从源头改，得先证明「不掉准确率」。
