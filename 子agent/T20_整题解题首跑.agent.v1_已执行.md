## 0. 一句话

让模型**只看题干和真题图**，自己把一道物理大题分步解出来，产出能进 Schema 1.2 的 answer JSON。

这是整个项目**第一次**验证「模型能不能分步解题」。此前 7 份 JSON 全是人写的（`meta.mode = "gold"`），采分点、Schema、L1–L4 校验、解析页，全部建立在一个**从未验证过的假设**上。

**本卡的目的不是刷分，是把「能不能」变成一个有数字的事实。**

## 2. 要写的三个文件（全部放 `评测/T20/`）

| 文件 | 作用 |
|---|---|
| `prompt_v1.md` | 解题提示词。要求模型输出**草稿格式**（§3），不是完整 Schema |
| `draft_to_schema.py` | 草稿 → Schema 1.2 的转换器（§4） |
| `run_solve.py` | 读题 → 发请求（含图）→ 拿草稿 → 转换 → 落盘 → 调校验 |

**为什么不让模型直接吐 Schema 全字段**：`checks`、`criterion`、`segment_id`、`law_ids` 这些是验证器和拆解规范的事。硬要求模型填，它只能编 —— 编出来的 `checks` 会让验证器「全部通过」，等于自己给自己盖章。**模型只负责「怎么解」，字段补齐归代码。**

## 3. 草稿格式（模型只输出这个）

字段名故意短，省 token。**必须是严格 JSON，不带 markdown 代码块**。

```json
{
  "sub_results": [
    {"no": "(1)", "result": "Ep_max = 0.6·m·v0²", "steps": [1, 2, 3, 4, 5]}
  ],
  "steps": [
    {
      "no": 1,
      "title": "从 v-t 图读出 B 的碰前速度",
      "kind": "judgment",
      "stmt": "由图 (b) 纵轴 t=0 处读出，B 碰前速度为 1.2v0，A 静止。",
      "eq": null,
      "value": null,
      "score": 1,
      "point": "读出 1.2v0，且明确说明来自图 (b)"
    },
    {
      "no": 2,
      "title": "碰前到共速的动量守恒",
      "kind": "equation",
      "stmt": "碰前 B 速度 1.2v0、A 静止；t=t0 时两者共速 v0。取碰前速度方向为正。",
      "eq": "m*1.2*v0 - (M+m)*v0",
      "value": null,
      "score": 2,
      "point": "列出动量守恒式，且正确代入共速 v0"
    }
  ]
}
```

**硬规则，写进 prompt 里：**

| 字段 | 规则 |
|---|---|
| `kind` | 只能取 `equation` / `value` / `judgment` / `discussion`。**`judgment` 的 `eq` 必须 null；`equation` 的 `eq` 必须非 null** |
| `eq` | **sympy 表达式，含义是 `eq = 0`**。不要写等号，不要写 LaTeX。`3mg = mv²/R` 要写成 `3*m*g + m*g - m*v**2/R`。乘法只用 `*`，幂用 `**`，除法用 `/` |
| `value` | 有确定数值时给 `{"symbol":"v","number":4,"exact":null,"unit":"m/s"}`；纯符号解给 `{"symbol":"v","number":null,"exact":"sqrt(2*g*R)","unit":"m/s"}`；无则为 null |
| `score` | **本步值几分（整数或 0.5 的倍数）**。同一小问下所有步的 `score` 之和**必须等于题目给出的该问总分** |
| `point` | 一句话说清这一步的采分点是什么。**这是模型对「给分点」的理解，是本卡最重要的观察对象之一** |
| `stmt` | 这一步怎么想的，给人看的话。允许写「由图 (b) 读出」这种 |
| `title` | ≤ 14 字 |

**不给模型的信息（给了就是泄题）**：金标 `steps[]`、`grading`、`figures[].provides`、`figures[].caption`、`situation.given[]`、采分点表、错误码表。

> `caption` 尤其不能给 —— 它是人工写的图题，A-02 的 caption 已经把「四个读数在图上」写出来了。

## 4. 转换器要补的字段

| Schema 字段 | 从哪来 |
|---|---|
| `schema_version` | 固定 `"1.2"`（若 T08e 已把库升到 1.2.1 则用 `"1.2.1"`，先 `ls` 确认） |
| `meta` | 抄原题的 `meta`，改三处：`mode="model"`、`model="deepseek-flash"`、`prompt_version="p1"` |
| `question` | **原样抄**（题干 + figures 的 fig_no/caption/is_required），`captions` 不进模型输入但产物里保留 |
| `situation.given` | **模型没给就留空数组**，不要从金标抄。这是观察「模型会不会自己抽已知量」的窗口 |
| `steps[].step_id / point_id` | `f"{answer_id}-S{no:02d}"` |
| `steps[].segment_id` | 首跑统一 `"SEG-01"`，不分段。分段能力不在本卡验证范围 |
| `steps[].law_ids` | `[]`。模型不填，不许从金标抄 |
| `steps[].criterion` | `judgment` / `discussion` 步由 `point` 生成 `{"expr":null,"expected":null,"comparator":"label","text":point}`；其余为 null |
| `steps[].checks` | `[]`，转换后由现有验证器跑出来再回填 |
| `steps[].confidence` | `null`（模型自评不可信，见红线） |
| `steps[].status` | `"draft"` |
| `grading.point_hits[]` | 由每步 `score` 生成，`hit: true` 仅表示「模型声称拿到」，**不是评测结论** |
| `grading.score_total` | 抄 `meta.full_score` |
| `grading.score_awarded` | **留空不填**。谁给的分必须另行人工核，不许让转换器算 |
| `validation` | 跑 `验证器/runner.py` 得到 |
| `triage` | 由脚本按现有规则生成，不许模型填 |

## 5. 为什么用这些模型参数

| 参数 | 值 | 理由 |
|---|---|---|
| `model` | `deepseek-flash` | 唯一收图的模型。**不许用 v4-pro，传图必失败** |
| `temperature` | **0.2** | 首跑要可复现。同题两次差异过大，说明结果不能当基线 |
| `max_tokens` | **16000** | A-02 有 15 步、带长式子。给少了会截断在半句上，看着像「模型不会」其实是没写完 |
| 图 | base64 内联 `data:image/png;base64,...` | 不依赖任何图床 |
| 重试 | 最多 1 次 | 只在「JSON 解析失败」时重试；**答案错不重试**。重试会挑出运气好的那次，是作弊 |

### 阶段 A：只跑 B-20（1 题）

选它的理由：**唯一两道图都齐、且 10 步 14 分结构完整的题**。链路问题会在这里全部暴露。

通过条件（三条全满足才算过）：

1. 模型返回**能被 `json.loads` 解析**的草稿
2. 转换后的 JSON 过 `validate_schema.py`（允许 WARN，不允许 E）
3. 跑完 `验证器/runner.py`，L1–L4 至少 L1 或 L2 有实际结论（不接受四层全 `na`）

**不过就别进阶段 B**，把卡退回 T00 说明卡在哪一步（是 prompt 问题、解析问题、还是 Schema 问题）。

### 阶段 B：跑全部 7 题，按有无图分两组

| 组 | 题 | 意义 |
|---|---|---|
| **带真图** | A-02（图2）、B-09（图1）、B-20（图甲+乙） | 考的是「会不会看图」 |

**这个对照本身就是结论的一半**：纯文字组如果答得跟带图组一样好，而这些题又都是 2021–2025 高考真题 —— 那说明模型**记住了原题**，不是会做。这正是 G5 主指标要抓的东西，报告里必须单列一组数字，不要混在一起算总准确率。

## 7. 判据：硬门槛 + 三个观察量 + 三档结论

### 硬门槛（不过就是红）

- 7/7 的草稿都能 `json.loads`
- 7/7 转换后 Schema 无 E
- 至少 5/7 的 L1 或 L2 有实际结论

### 三个观察量（都要出数字，不合并）

| 观察量 | 怎么算 | 为什么单列 |
|---|---|---|
| **步数比** | 模型步数 ÷ 金标步数 | 模型倾向合并步骤。10 步压成 5 步，意味着采分点粒度对不上，判分器将来无从下手 |
| **分点命中率** | 人工逐点核：模型的 `point` 与金标 `point_hits` 是否等价 | **必须人工核**。等价写法（「支持力」vs「轨道对物块的作用力」）机器判不了。分母写明「金标 N 点」 |
| **图上读数正确率** | 模型从图上读出的值与 `provides` 比，容差 ±3% | 容差 3% 不是放宽标准，是因为 **B-20 图自己的作图误差就有 3%**（折合斜率 0.485/0.994，真值 0.5/1.0） |

### 三档结论

| 档 | 条件 |
|---|---|
| **绿** | 分点命中 ≥ 60% **且** 步数比在 0.7–1.3 **且** 图上读数全对 |
| **黄** | 命中 30–60%，或步数比越界，或读数部分错 |
| **红** | 命中 < 30%，或硬门槛不过 |

**报告里三档都要写清是「哪一条挂的」。「黄」不带解释等于没结论。**

## 8. 不许做的事（红线）

1. **不许把 `caption` / `provides` / 金标 `steps` 喂给模型。** 一句都不行。这是全卡最容易被无意破坏的地方 —— 调试时顺手贴一段金标，整批数据就废了。
2. **不许手工修 JSON 让它过校验。** 模型输出不合规，就记一条 issue。改了就是掩盖。
3. **不许让模型自评置信度再拿来当结论。** `confidence` 一律 null。项目红线：不拿模型自评定阈值。
4. **不许在答案错时重试。** 只在 JSON 解析失败时重试 1 次。挑运气好的那次是作弊。
5. **不许报「准确率 XX%」而不写分母。** 写「分点命中 12/27」而不是「44%」。分母是金标点数还是模型步数，必须说清。
6. **不许拿金标的分值去反推模型的分值。** 模型分错了就是分错了，那是最值钱的观察。
7. **余额低于 1 元就停，不要跑空。** 402 要立即终止整批，不要循环重试。

## 10. 已知风险（开工前先认）

| 风险 | 应对 |
|---|---|
| 模型把 10 步压成 5 步 | **这是真实能力，不许逼它拆**。如实记步数比，这正是要观察的 |

| 模型给的 `eq` 是 LaTeX 或带等号 | 转换器做一次归一（去 `=`、去 `\\frac`），归一不了记 issue 并置 null，**不许自己代数** |
