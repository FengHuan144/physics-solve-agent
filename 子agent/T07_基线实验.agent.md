## 0. 一句话与三条边界

**一句话**：用 3 个 prompt 变体，把 22 道有完整原文的真题裸问一遍，记录最终答案对错、耗时、token、失败类型，按「依赖图 / 过程数 / 题型」三层拆开报。

**边界（越界即作废）**

1. **不给图，也不把图翻译成文字**。题干里的 `[图1｜位置｜图题]` 标记原样保留——那是原文的一部分，也是真实场景：模型看不到图。把几何关系补成文字，等于替模型做题，基线立刻失效。
2. **不用采分点判分**。你只判「最终答案对不对」。过程跳步、方程写法不在你的范围（那是 G3 验证器的事）。
3. **不改任何已有文件**。xlsx、schema、知识表、题干原文全部只读。你只写 `评测/基线/` 下的东西。

## 1. 开工前必须想清楚的五件事

### 1.1 基线不是「考模型」，是量出缺口在哪

只报一个「准确率 43%」的数字，这个实验白做。必须分层，而且**第一层就是「题目要不要图」**：

| 分层 | 题数 | 为什么必须分开 |
|---|---|---|
| 依赖图 | **6**（B-04 / B-09 / B-15 / B-17 / B-18 / B-20） | 不给图，这 6 道大概率全错。混进总数会把准确率拉低约 27 个百分点 |
| 不依赖图 | **16** | 这 16 道才是「纯文字推理能力」的真实读数 |

**不分开，你会得出「模型不行」的结论，而真相是「我们没给它图」。** 这两个结论对应完全不同的下一步。

第二层按过程数：1 过程 **3** 题 / 2 过程 **7** 题 / 3 过程 **11** 题 / 4 过程 **1** 题（A-08）。
第三层按题型：匀变速 2 / 力平衡 3 / 牛顿定律 4 / 能量 8 / 动量 2 / 圆周临界 2 / 万有引力 1（有交叉，按主考点归一道）。

### 1.2 只能跑 22 题，不是 29 题——这不是偷懒，是事实

`采分点/题干原文/` 只有 **22** 份（A-06 / A-08 / A-09 / A-10 + B 组 18 题）。
**A-01~A-05 没有完整原文**：它们只有 xlsx 里的 40–80 字要点，和五卷讲义 HTML 里的散段落，没有整理成 8 节格式。

所以：基线是 **22 题 / 260 分**，报的时候必须写「22/29，A-01~A-05 缺完整原文」。**不许拿要点当题干去问模型**——要点丢条件，测出来的不是同一道题。

### 1.3 判分只能用最终答案，因为采分点只齐 6 题

| 判分方式 | 能判几题 | 结论 |
|---|---|---|
| 采分点命中率 | **1 题**（只有 A-06 有完整原文 + 采分点） | 不可用 |
| 最终答案比对 | **22 题** | 采用 |

代价：判不出「答案对但过程全错」。所以加一道 **5 题抽查**：从「答案判对」的题里随机抽 5 道，人读一遍过程，标「真会 / 疑似蒙对」。这 5 题不进主指标，单独报。

**G2 基线的指标是「端到端最终答案正确率」，不是「采分点命中率」。这两个数不许混在一张表里。**

### 1.4 变体 3 的例题不能来自 22 题

「带例题」变体如果拿评测集里的题当例子，等于泄题。例题必须是**不在 22 题内、且题型不同**的一道极简题。

卡里给一道可以直接用的（自造，不是真题，不涉及任何评测题解法）：

```
例题：一辆小车从静止开始以 2 m/s² 的加速度匀加速直线运动，求 5 s 末的速度和这 5 s 内的位移。

解答：
1. 研究对象与过程：小车，单段匀加速直线运动。
2. 方程：由 v = v₀ + at 得 v = 0 + 2×5；由 x = v₀t + ½at² 得 x = 0 + ½×2×5²。
3. 结果：v = 10 m/s，方向与加速度同向；x = 25 m。
4. 讨论：本题无临界、无舍根，单解。
```

### 1.5 三道必须跑通的闸，不要一次跑 66 次

```
第 1 道：1 题 × 1 变体  → 检查：有没有返回、格式是否可解析、usage 字段在不在
第 2 道：22 题 × 1 变体  → 检查：判分表能不能覆盖、有没有 undecidable 堆积
第 3 道：22 题 × 另 2 变体 → 全量
```
66 次调用跑完才发现 JSON 字段名写错，是最常见的浪费。

## 4. 硬规则（编号即验收项）

- **R1 全覆盖**：22 题 × 3 变体 = **66** 条，一条不许少。跑失败的题写进报告，不许静默消失。
- **R2 原始响应落盘**：`raw/{variant}/{qid}.json`，含完整 `content`、`usage`、`model`、耗时。**只存解析结果不存原文，后面做不了归因。**
- **R3 prompt 版本化**：`prompts/` 下三个文件，跑完锁死。中途改一句，前 22 条就作废。
- **R4 温度固定**：`temperature=0`。若接口不支持 0，用最低值并在报告里写明实际值。**不许各变体用不同温度。**
- **R5 重试上限 2 次**：仍失败记 `api_error`，继续下一题。因长度截断的记 `truncated`，**不算错**。
- **R6 token 与耗时必记**：每题每变体一行。
- **R7 三态判分**：`correct` / `wrong` / `undecidable`。`undecidable` 不计入准确率分母，但必须单独报数量与题号。
- **R8 答案比对规则**（写进 `answers_std.csv` 的 `tolerance_rule` 列）：
  - 题干给 `g=10` 的，按 10 判；没给的，**10 与 9.8 各算一次，命中任一即 `correct`**，并记 `g_used`。
  - 有效数字：`3.2 s` 与 `3.20 s` 同判对；容差取相对 **2%**（覆盖四舍五入与 g 取值差异）。
  - 非数值答案（如 B-01 的「4 号锥筒」、方向描述、区间）标 `undecidable`，**不许硬判错**。这类题在报告里单列。
  - 多解题（B-02 竖直上抛两解、A-02 碰撞两解）：答全才 `correct`，只答一解 `wrong` 并记 `missing_root`。
- **R9 不许提示**：prompt 里不许出现「采分点」「按步骤给分」「这题考的是…」。
- **R10 观察项单列**：记录模型是否**主动说出**「缺少图信息／无法确定几何关系」。这是「模型知不知道自己缺什么」的证据，单独统计，不混进准确率。
- **R11 题干指纹必存**：跑之前对每份原文算 `sha256`（UTF-8 原文字节），存 `stem_fingerprints.csv`（`qid, file, sha256, 小问数, 卷面分`）。
  理由：`采分点/题干原文/` 是**活文件**——2026-11-25 08:40 刚回写过 B-10（分值改 9）、B-18（题号改 16）等裁定。没有指纹，就无法证明「这张基线表跑的是哪一版题干」，也无法在题干变动后判断要不要重跑。
  这个字段在 Schema 里已经有对应项（`question.stem_sha256`），不是新发明。
- **R12 缺输入 ≠ 答错**（2026-11-25 新增，依据 C14 与 `采分点/依赖图复核_20261125.md`）：依赖图组的题不给图，错因是**输入缺失**，不是能力不足。
  - 模型明确说「缺少图信息／无法确定」的，判 `undecidable`，归因写 `input_missing`，**不进 `wrong`**。
  - 模型硬答且答错的，判 `wrong`，归因写 `guessed_without_figure`，与前者分列。
  - **B-20 与 A-02 属「图即数据源」**（a–F 图线斜率截距 / v–t 图数值只在图上），文字版根本不含解题数据。这两道的 `wrong` 不计入任何能力统计，只作「无视觉输入时的表现」记录。

## 5. 交付物

```
评测/基线/
  prompts/v1_zero.md  v2_role.md  v3_fewshot.md
  raw/{v1,v2,v3}/{qid}.json          66 份
  answers_std.csv                    22 题标准答案结构化表
  scores.csv                         66 行
  report.md                          分层报告
  run.py                             可复现脚本（读 prompts → 调 API → 写 raw）
  score.py                           判分脚本（读 raw + answers_std → scores.csv）
```

### `answers_std.csv` 列

`qid, sub_no, answer_raw, answer_value, unit, is_multi, decidable, tolerance_rule, note`

- `answer_value` 多解用 `|` 分隔（`4.0|1.0`）
- `decidable` = `yes/no`，`no` 的题判分时直接走 `undecidable`
- 这张表要**人工核过一遍**（抽 5 行对原文 §6），核的人写在 `note` 里

### `scores.csv` 列

`qid, variant, verdict, g_used, elapsed_s, prompt_tokens, completion_tokens, failure_type, notes`

`failure_type` 取值：`none` / `no_figure`（明说缺图）/ `calc`（算错）/ `method`（方法错）/ `miss_root`（漏解）/ `truncated` / `api_error` / `format`（答非所问）

### `report.md` 必须有的四张表

1. 总表：3 变体 ×（correct / wrong / undecidable / 准确率）
2. **依赖图分层**：6 题 vs 16 题，各变体准确率
3. 过程数分层：1 / 2 / 3 / 4
4. 题型分层：7 类
5. 观察项：主动说缺图的题数；`truncated` 数；5 题抽查结果（真会/疑似蒙对）

## 7. 已知陷阱（都是这个项目真踩过或必然踩到的）

| # | 陷阱 | 后果 |
|---|---|---|
| 1 | 把 6 道依赖图的题混进总准确率 | 结论从「缺图」歪成「模型不行」 |
| 2 | 把 caption 拼进题干 | 等于把图翻译成文字，违反项目铁律，基线作废 |
| 3 | v3 的例题用了评测集里的题 | 泄题，v3 准确率虚高 |
| 4 | 判分容差按 0.1% 卡 | g 取 9.8 的题全被判错，准确率虚低 |
| 5 | 只存解析结果、不存原文响应 | 做不了归因、建不了错例库，要重跑一遍 |
| 6 | A-01~A-05 用 xlsx 要点当题干 | 要点是压缩件，测的不是同一道题 |
| 7 | 用 shell 的 grep/sed 抽中文题干 | Git Bash 下多字节会被切坏（本卡编写时已踩过），一律用 Python |
| 8 | `max_tokens` 给小了 | 长解答被截断，记成 `wrong` 而不是 `truncated` |
| 9 | 三变体各用不同 temperature | 三个数不可比，整张表作废 |
| 10 | 报「29 题基线」 | 实际只有 22 题有原文，虚报会被追问穿 |

## 8. 回报格式

```
变体：v1/v2/v3
完成：22/22
准确率：总 X% ｜ 依赖图 6 题 X% ｜ 不依赖图 16 题 X%
undecidable：N 题（逐题列）
truncated / api_error：无 / {题号 + 原因}
主动说「缺图」的题：N 题（题号）
5 题抽查（真会/疑似蒙对）：{qid: 真会} …
token：总 N ｜ 单题均值 N ｜ 单题最高 N（题号）
实际模型名与 temperature：……
需要裁定：无 / {具体问题，不要自行决定}
```

**最后一条最重要**：判分表拿不准的（非数值答案、多解、单位换算），留 `undecidable` 抬到「需要裁定」，**不要静默判错**。主 agent 会做决定。
