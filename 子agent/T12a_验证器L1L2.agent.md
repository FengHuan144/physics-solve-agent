## 0. 一句话与三条边界

**一句话**：实现两个可自动化的检查层——**L1 计算**（sympy 回代自洽）与 **L2 量纲**（pint）——输入一道题的结构化步骤，输出每步的 `checks[]`，格式严格对齐 `schema/answer.schema.json` 的 `check` 定义。

**边界（越界即作废）**

1. **不做视觉前置**。caption 管线、VLM、读图全部不在本卡（那是 T12b，卡还没写）。
2. **不改 Schema**。`checks[]` 的四个字段、`status` 的四个取值、21 条错误码，全部是既定契约。你只能往里填，不能增删。
3. **不判「建模对不对」**。方程建错了但自洽、量纲也对——L1/L2 抓不到。这是方案第 7 节写死的边界，不许在报告里含糊过去。

## 1. 开工前必须想清楚的五件事

### 1.1 口径：L1 是计算，L2 是量纲。PDF 里写反了，别跟 PDF

| 来源 | L1 | L2 | 状态 |
|---|---|---|---|
| 方案 PDF §05 指标表 / §08 线框 | 量纲 | 回代 | **用反了，不采用** |
| `原始资料/agent.md` §2.2 | 计算 | 量纲 | 一致 |
| 采分点表「错误码枚举」检测层列 | E-10 代入代数错 → **L1** | E-11 单位缺失 / E-12 量纲不符 → **L2** | **采用** |

裁定写在 `schema/字段清单.md` §0。**你按 L1=计算、L2=量纲实现。** 这一条搞反，全部错误码归因反掉，整个质检面板的结论都是错的。

### 1.2 「回代」不等于「解方程」，必须两种模式都做

高中物理解题是**先列一堆方程、最后联立**。要求每步都能解出来，等于把正常步骤判成失败。

所以要分两个模式，各自输出：

| 模式 | 判什么 | 能抓的错误码 | 判不了的 |
|---|---|---|---|
| `per_step` | 用前序步骤的 `value` 当已知，本步方程能否解出本步 `value`，代回残差是否为 0 | E-10 代入代数错 | 列方程步（本来就没有 value）→ `na` |
| `chain` | 全题所有方程联立：是否相容、是否唯一解、解是否等于各步 `value` | E-10、E-04 项遗漏、E-13 末态漏项 | 方程本身建错（那是 L5） |

**只做 `per_step`** → 大量 `na`，等于没检查。
**只做 `chain`** → 定位不到是哪一步错。
两个都要，结果合并写进 `checks[]`（同一层只出一条，detail 里写清是哪个模式判的）。

### 1.3 欠定不是失败

「3 个未知数、1 个方程」是**正常**的列方程状态。

Schema 的 `check.status` 只有 `pass / fail / na / skipped` 四个值，**没有 `undetermined`**。

映射规则（写死，不许自创）：

| 情形 | status | detail 写法 |
|---|---|---|
| 方程相容、残差 0 | `pass` | `回代残差 0（per_step）` |
| 方程矛盾（无解） | `fail` | `方程组矛盾：<哪两个方程冲突>` |
| 欠定（方程数 < 未知数） | `na` | `欠定：3 未知 / 1 方程（chain 可解，本步不判）` |
| 该步 `parse_status=degraded` | `skipped` | `解析降级，本层停用` |
| 该步是 `judgment` / `discussion` / `critical`，无方程 | `na` | `非方程步` |

`skipped` 是 Schema 里有专门含义的值（因 degraded 停用该层），**不许拿它当 `na` 用**。

### 1.4 量纲检查抓不到「单位换错」

这是最容易误解的一条。举例：题干给 `L = 5 cm`，模型写成 `L = 5 m` 代入。

- 量纲：两边都是长度，**一致** → L2 判 `pass`
- 数值：差 100 倍 → 只有 L1 的残差能抓到，且**只在有 value 可比时才抓得到**

所以 L2 的边界必须写在报告里：**L2 只保证「单位类型对」，不保证「单位数值对」。** 单位换算错了要靠 L1 的 `value` 比对。

### 1.5 能抓什么、抓不到什么（照抄进报告的局限一节）

| 错误码 | 含义 | L1/L2 能抓？ | 说明 |
|---|---|---|---|
| E-10 | 代入代数错 | ✅ L1 | 本卡的主目标 |
| E-04 | 项遗漏 | ⚠️ 部分 | 只有当遗漏导致方程组矛盾时才抓得到 |
| E-13 | 末态能量漏项 | ⚠️ 部分 | 同上 |
| E-06 | 正方向/符号错 | ⚠️ 部分 | 符号错常表现为残差非 0，但不是必然 |
| E-11 | 单位缺失 | ✅ L2 | `value.unit` 为空即报 |
| E-12 | 量纲不符 | ✅ L2 | |
| E-02 | 几何投影遗漏 | ❌ | 漏 `sinθ` 后方程仍自洽，抓不到 |
| E-03 | 过程分段错位 | ❌ | 那是 L4 |
| E-15 | 临界条件误判 | ❌ | 那是 L5 |
| E-21 | 有结论无依据 | ❌ | 那是 L5 |

**报告里必须原样列出这张表的 ❌ 行。** 验证器不是判分器，说它能判对错就是撒谎。

## 3. 实现要点

### 3.1 L2 量纲：手写递归遍历，别指望 pint 直接吃 sympy

pint 没有稳定的 sympy 集成。可行做法是自己写一个表达式遍历，叶子节点转成 `ureg.Quantity(1, unit)`：

```python
def dim_of(expr, unit_map):
    # Symbol → Quantity(1, unit)
    # Add    → 所有项量纲必须相同，否则 E-12
    # Mul    → 量纲相乘
    # Pow    → 量纲取幂（指数必须是无量纲数）
    # Function(sin/cos/tan/exp/log) → 参数必须无量纲
    # sqrt   → Pow(1/2)
```

单位来源：**只用白名单的 `单位_SI`**（`meter/second`、`newton/kilogram`），不要用题干里的 `m/s`——白名单是唯一准入名单，题干写法有四种变体。

### 3.2 L1 计算：三件事

```python
# 1) 收集已知：所有 value.number != null 的步 → {symbol: Quantity}
# 2) chain：全部 equation 联立，代入已知，sympy.solve 剩余未知
#    - 无解 → fail（报矛盾涉及哪两步）
#    - 解不唯一 → na（欠定），detail 写清自由变量
#    - 唯一解 → 与各步 value 比，相对误差 > 2% → fail
# 3) per_step：对每步单独，前序 value 代入，看本步 value 是否满足本步方程
```

**容差**：相对 **2%**。理由和基线判分一致——`g` 取 10 或 9.8 会差 2%，有效数字四舍五入也在这一档。绝对值小于 `1e-9` 的按 0 处理。

**不许用 `eval()`。** 一律 `sympy.sympify(expr, locals={...})`，且 `locals` 只放白名单里的符号名。

### 3.3 输出：填 Schema 的 `checks[]`，不自创格式

```json
{"layer": "L1", "status": "fail", "detail": "回代残差 3.6（期望 0）；第 4 步代入 v2=3 时方程不成立",
 "error_code": "E-10"}
```

- `layer` 只能是 `L1/L2/L3/L4`（本卡只产 L1、L2）
- `status` 只能是 `pass/fail/na/skipped`
- `error_code` 必须在 21 条里（见 xlsx「错误码枚举」）
- **一条 check 一个错误码**，多个问题拆多条

## 4. 硬规则（编号即验收项）

- **R1 61 步跑通**：`采分点总表` 全部 61 步，0 崩溃、0 未捕获异常。
- **R2 人造反例必须被抓住**：至少 6 条，覆盖
  - `E-10`：把 `v = 3` 改成 `v = 4`（残差非 0）
  - `E-12`：把 `m*v` 改成 `m*v**2`（量纲不符）
  - `E-11`：`value.unit` 置空（单位缺失）
  - `E-04`：方程删掉一项（若导致矛盾，应报 fail；不矛盾则**如实报抓不到**，不许硬凑）
  - 欠定：单方程三未知 → 必须 `na`，不许 `fail`
  - degraded：`parse_status=degraded` → 必须 `skipped`，不许参与统计
- **R3 输出过 Schema 校验**：用 `jsonschema` 对 `definitions.check` 逐条验证，0 违约。
- **R4 幂等**：同一输入跑两次，结果逐字节一致（sympy 的 `solve` 有时返回顺序不定，要排序）。
- **R5 不静默修数据**：遇到 `sympy` 串里有等号、符号不在白名单、单位不是 pint 串——**报 `data_error` 并跳过该步**，不许自己改。
- **R6 降级不参与统计**：`parse_status=degraded` 的步不进 L1/L2 的分子分母。这条照 Schema 字段清单 §4。
- **R7 边界写进报告**：§1.5 那张表的 ❌ 行必须原样出现在 `验证器/说明.md` 里。

## 7. 已知陷阱

| # | 陷阱 | 后果 |
|---|---|---|
| 1 | 跟着 PDF 把 L1 写成量纲 | 全部错误码归因反掉，面板结论全错 |
| 2 | 欠定判成 fail | 大量「列方程」步被冤判，验证器不可信 |
| 3 | 用 `skipped` 表示「不适用」 | `skipped` 专指 degraded 停用，混用后停用率统计失真 |
| 4 | `sympify("1/2")` 与 `sympify("0.5")` 混用 | 精确相等判断失败，出现假阳性 |
| 5 | 符号 `M` 与 `m` 被 lower() 成同一个 | 质量比全错，回代必炸 |
| 6 | 单位用题干的 `m/s` 而不是白名单的 `meter/second` | pint 解析失败，L2 整层不可用 |
| 7 | 用 `eval()` 求值 | 安全问题 + 希腊字母解析不了 |
| 8 | 只做 per_step 不做 chain | 61 步里大部分是列方程步，全 `na`，等于没检查 |
| 9 | 遇到等号就自己 split | 掩盖上游数据问题，错误被吞 |
| 10 | 把「残差非 0」一律报 E-10 | 项遗漏（E-04）、符号错（E-06）也表现为残差非 0，要按方程结构区分 |
