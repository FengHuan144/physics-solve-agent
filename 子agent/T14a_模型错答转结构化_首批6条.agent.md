## 2. 输出格式（**独立文件，不是 schema 的一部分**）

写 `评测/对齐/model_answers_v1.json`：

```json
{
  "meta": {
    "built_at": "2026-11-25T...",
    "schema_note": "本文件是对齐表，不属于 answer.schema（schema 只描述金标答案）。式级对齐属 Schema 1.3，本卡不碰契约。",
    "source": "评测/基线/raw/",
    "gold": "schema/examples/ + 采分点总表 223 步"
  },
  "items": [
    {
      "qid": "A-09", "variant": "v1",
      "raw_file": "评测/基线/raw/v1/A-09.json",
      "verdict": "wrong", "failure_type": "calc",
      "segments": [
        { "i": 1,
          "quote": "……原文逐字摘录……",
          "step_id": "A-09-S03",
          "role": "equation | value | judgment | setup | chatter",
          "confidence": "high | low",
          "note": "为什么对到这一步；对不上就写清理由" }
      ],
      "unaligned": [
        { "quote": "……", "reason": "跑题 / 重复 / 只有结论无过程" }
      ]
    }
  ]
}
```

字段纪律：

- `quote` **必须是 raw `content` 里的逐字子串**（脚本会验，见 §5），不许改写、不许省略号代替、不许拼接两处
- `step_id` 只能取该题在采分点总表里真实存在的步号；**对不上就放 `unaligned`**，不许硬塞
- `role` 里 `setup`＝研究对象/过程声明、`chatter`＝寒暄/自我检查，这两类通常不该挂 step
- **`confidence: low` 要写 `note` 说明歧义在哪**，别用 low 掩盖没想清楚

## 3. 一条要单独标的情况

`B-20 / v3` 的 `failure_type` 是 `guessed_without_figure`：模型**自己把图上的数补出来**（写出了 `M`、`F=8 N`、`a` 的具体值，但题干文字一个都没给）。对齐时额外加一个布尔字段：

```json
{ "quote": "……", "step_id": "B-20-S04", "invented_from_figure": true, "note": "题干未给 a–F 图读数，此处为模型自行补出" }
```

这条是**唯一一条「缺图时模型会怎么做」的实证**，标错就白费了这批数据。

## 4. 不许做的事

1. **不许判对错**。`scores.csv` 已经判完了，本卡不重判。你若发现 `scores.csv` 判错了，写进「需上报」一节，不许自行改判。
2. **不许润色模型原文**。错的地方要原样留着 —— 那正是要被批改的东西。
3. **不许补写模型没说的话**。哪怕它跳步跳得离谱，也照实记录跳步，不许替它补全过程。
4. **不许动 `评测/基线/` 下任何文件**（`scores.csv` / `raw/` / `report.md` 全部只读）。
5. **不许把这个 JSON 当成 answer schema 的扩展去改 schema**。要改契约另开卡。
