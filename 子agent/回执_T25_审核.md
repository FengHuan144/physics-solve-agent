## 三、发现的漏洞（已修，留痕）

**漏洞**：`credit=hit` 且 `score=0`、`score_range=[0,0]`、summary 全部自洽 → `contract.py` 报 **0 违约**。

**为什么危险**：S1 全是 `na`，这个洞现在不咬人；S2 起会产出真 `hit`，一旦归属逻辑写错（命中了但分值取成 0，或 merged 拆分时把分摊写成 0），契约仍会说 OK。这正是交接卡 C16 那 4 次的同型，只是这次投产前就撞上了。

**修法**（`判分器/contract.py` 第 102 行后 +2 行）：

```python
if credit == "hit" and score <= 1e-9:
    bad.append(f"{pid}: credit=hit 但 score={score}（命中必须给分；总表最小分值 1）")
```

前提已核：全表分值分布 `{1:110, 2:105, 3:8}`，**无 0 分点**，故该规则无条件成立；7 题内 `{1:36, 2:30}` 同样成立。

**复验**：7 份产物仍 0 违约；同一篡改件从「OK」变成「1 项违约」；`grader.py --all` 重跑后产物 md5 **未变**。

**另一处**：`grader.py` 第 35 行注释称「contract 会核对 basis 与版本是否自洽」，实际没有这个校验。已改为如实话术（`contract` 只校验字段存在，自洽要人看）。注释说谎比没注释更坏——下一个人会以为已经验过。
