## 0. 一句话与三条边界

**一句话**：Schema v1.0 只在 A-06（板块模型）一题上验过。把它扩到能表达 22 题的 7 类题型，用**每类一份真样例**证伪，只加必要的可选字段。

**边界（越界即作废）**

1. **只增不改**。`kind` 五值、`layer` 六值、`status` 四值、21 条 `error_code`、所有既有字段名——**一个字都不许动**。原因见 §1.1。
2. **不改采分点、不改题干原文**。你只写 `schema/` 下的东西。
3. **不追求「什么题都能表达」**。表达不了的，明确写「不表达 + 理由 + 降级方案」，比硬加字段好。加一个字段没人用，比缺一个字段更糟。

## 1. 开工前必须想清楚的四件事

### 1.1 只增不改，因为 T05b 正在跑

T05b 正在把 21 题拆成 17 列 CSV。它与 Schema 的耦合点只有两个：

| 耦合点 | 现状 | 你的处置 |
|---|---|---|
| `kind` 五类（judgment / equation / value / discussion / critical） | 对应采分点 ①②③④⑤ | **不许动**，T05b 的分类直接映射到这五个值 |
| `point_id` 格式 `A-06-S01` | 与采分点总表主键同形 | **不许动** |

其余字段（`outline`、`checks`、`triage`、`review`）T05b 不产生，可以加**可选**字段。

**判断标准**：加完之后，v1.0 的 `example_A-06.json` 必须**不改一个字**仍能过校验。过不了，说明你动了不该动的东西。

### 1.2 覆盖不是加字段，是拿真题打脸

每类题型做一份**真样例**（数据取自 `采分点/题干原文/` 与 xlsx 的 61 步，不许编），跑校验。

- 能过 → 这一类覆盖了
- 不能过，且缺的是**可选**信息 → 加可选字段，再跑
- 不能过，且缺的是**必填**信息 → **不许**把它改成必填（会废掉老样例），改为「写进局限」

### 1.3 必须覆盖的 7 类（按 22 题实际分布）

| # | 类 | 代表题 | 结构难点 | 必做样例 |
|---|---|---|---|---|
| 1 | 板块 / 多体牛顿 | A-06 | 两物体各自方程 + 共速条件 | 已有（回归） |
| 2 | 圆周 + 机械能 + 临界 | **A-08** | 4 过程；绳松弛/脱离轨道的判据 | ✅ |
| 3 | 万有引力 | A-10 | 天体质量、v–r 图读数 | — |

### 1.4 三个已知缺口，必须逐个表态

这三处是 v1.0 真实存在的表达盲区，不是猜的。**每处给「加字段 / 不加字段」的结论 + 理由 + 若不解决的局限。**

#### 缺口 a：图里的数据（B-20 的 a–F 图线、A-10 的 v–r 图）

`question.figures[]` 只有 `fig_no / caption / caption_source / is_required`，**没有「从图里读到哪些点」的字段**。

而 B-20 的 (ⅰ) 唯一数据源就是图乙的 a–F 图线（斜率 = 1/m，截距 = -μg）。A-10 的 (3) 也依赖 v–r 图。

**倾向结论（你可以推翻，但要给理由）**：不加字段。读数写进 `caption`（`caption_source: "human"`），并在 `is_required: true` 时把该题标记为「必须人工」。

理由：图数据本质是金标侧的中间产物，不是模型输入（模型看不到图，这是项目铁律）。加 `figure_data[]` 会让 Schema 长出「题库」的枝，与「结构化解析」的职责混淆。

**若不解决，局限是**：读数无法机器校验，B-20 / A-10 这类题的 L1 回代只能用人工确认的数值，误差来源分不清是读图错还是算错。

#### 缺口 b：多解（B-02 竖直上抛两解、A-02 碰撞两解）

`value` 是单个 `symbol + number`，表达不了「解集」。

**倾向结论**：不加字段。两条 `step`（每条一个 value）+ 一条 `kind: "discussion"` 的步写舍根理由。

理由：多解本来就是两个采分点或「一个解 + 一条讨论」，D1 规定采分点即骨架，硬塞进一个 value 反而破坏骨架。

**要验的**：用 B-02 做样例，看这样表达后 `grading.point_hits` 与 `missing_points` 还能不能算对。**验不过就如实报。**

#### 缺口 c：同一符号跨题不同义

`schema` 引用的是**全局**符号白名单（71 条）。`t2` 在 A-06 是平抛飞行时间，在别的题可能是另一段的时间。

**倾向结论**：不处理。每题一份独立 JSON，`meta.question_id` 已隔离；题内不重复定义即可。跨题复用同名符号不构成错误。

**要做的**：检查 22 题的「已知量」表，看有没有**同一题内**一符号两义的情况（那才是真错）。有就报出来。

## 3. 硬规则（编号即验收项）

- **R1 老样例零改动通过**：`example_A-06.json` 一字不改，校验 E 0 / W 0。
- **R2 枚举冻结**：`kind` / `layer` / `status` / `error_code` 的取值集合，与 v1.0 **完全相同**。用脚本 diff 证明（见 §5）。
- **R3 新字段必须 optional**：不进任何 `required` 数组。加进 required = 废掉老样例。
- **R4 3 份新样例必须是真题**：题干、小问、答案取自 `采分点/题干原文/`，不许编题。步骤可只覆盖前 k 步（Schema 允许部分完成，`outline[].expanded=false`）。
- **R5 三个缺口逐个表态**：`schema/覆盖报告.md` 里三节，每节给结论 + 理由 + 局限。**不许跳过。**
- **R6 不改校验器的撞 id 检查**：同 `point_id` 在 xlsx 与 CSV 双源时必须报 error（C11），可以在这之外加字段校验。
- **R7 版本号**：`schema_version` 从 `1.0` 改 `1.1`，并在 `schema/CHANGELOG.md` 记一行「加了什么、为什么、兼容性」。
- **R8 不静默改数据**：样例里遇到原文缺条件（如某题未给 g），写 `null` 并在 `assumptions[]` 记一笔，不许自己补 10。

## 6. 已知陷阱

| # | 陷阱 | 后果 |
|---|---|---|
| 1 | 为了让新样例过，把某字段改成 required | v1.0 老样例立刻挂，且 T05b 产出对不上 |
| 2 | 改 `kind` 枚举（比如加 `setup`） | T05b 的五类分类白干，整个骨架错位 |
| 3 | 编 `point_id`（A-08-S01 之类） | 造假数据，T05b 拆完会撞 id |
| 4 | 为「什么题都能表达」无限加字段 | Schema 变成题库，没人用，维护成本全落在后面 |
| 5 | 图数据塞进 `stem_text` | 违反「图不文字化」铁律，评测失真 |
| 6 | 削弱 `validate_schema.py` 的撞 id 检查 | 双事实源回归，A-06 入册时踩过的坑 |
| 7 | 样例只写 1 步就交 | 部分完成是允许的，但要标 `outline[].expanded=false`，否则看起来像跑通了 |
