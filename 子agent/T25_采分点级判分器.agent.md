### 三条容易踩的输入陷阱

1. **学生答案是 free 模式，`point_id` 全为 null。** 归属（哪一步在说哪个采分点）**要你自己算**。这就是「point-centric 反查证据」的全部工作量——不是把 101 步摊到 66 点上。

## 3. 输出契约（本卡最重要的部分，比算法重要）

逐点一行，四要素缺一不可。下面的例子**只摘 A-02 的 3 个点**（该题实际 15 点），`summary` 也只按这 3 点算——**故意这么写，是为了让你一眼能验算**：1 + 1 + 0 = 2.0 分，1 + 2 + 2 = 5 分。

```json
{
  "qid": "A-02",
  "mode": "free",
  "points": [
    {"point_id": "A-02-S01", "credit": "hit", "score": 1.0, "score_range": [1.0, 1.0],
     "by": ["A-02-S03"], "basis": "口径「只写速度相同未推出每段损失相同仍给分」→ 模型 S03 给出相邻段重复",
     "uncertain": false},
    {"point_id": "A-02-S06", "credit": "hit", "score": 1.0, "score_range": [0.0, 2.0],
     "by": ["A-02-S08"], "basis": "merged：一步同时承载 S06 与 S07；给了「质心匀速」、未给「相对简谐」，2 分拿不满",
     "uncertain": true},
    {"point_id": "A-02-S11", "credit": "na", "score": 0.0, "score_range": [0.0, 2.0],
     "by": [], "basis": "步内符号不在白名单，L1 与 L2 均无可判结论", "uncertain": true}
  ],
  "summary": {"total": 3, "hit": 2, "miss": 0, "na": 1,
              "score": 2.0, "score_total": 5,
              "judged_rate": "2/3"}
}
```

> 上例三点分值取自总表：`A-02-S01`=1、`A-02-S06`=2、`A-02-S11`=2。**示例若算不平，产物必然算不平**——先验算，再实现。

### 六条硬约束（违反任一条，产物作废）

1. **不许只出题级分数。** 题级 `summary.score` 必须能由 `points[].score` 求和得到——同一份产物里两个数必须互相可推导。这条是为了堵 `B-20` 那个洞：首跑出现题级 13/14 与点级 9/10 两个独立落笔的数，中间没有任何东西绑定（`评测/对齐/B-20失分对不上_复核_20261125.md`）。
2. **`na` ≠ `miss`。** `na` = 判不了（符号不在白名单、merged 分摊、无锚点），`miss` = 判了没拿到。两者**分开计数、单独占一格**；`na` 既不许并入 `miss`，也不许并入 `hit`。把 na 当 miss 会让准确率凭空掉一截，且掉的是**我们自己的盲区**，等于栽赃给学生（与 `评测/基线/score.py` 的三态口径一致：undecidable 不进准确率分母）。
3. **`by` 必须指向具体 `step_id`。** 命中却指不出哪一步 = 没命中。空数组只允许出现在 `credit=na` 或 `miss` 上。
4. **`score` 与 `score_range`：** 正常点两者相同；`merged` 点只给区间 + `uncertain=true`，**禁止机械对半分**（`A-02-S06` 该扣 1 还是 0，人判也判不出，见裁定书 R2）。
5. **每条 `basis` 要能落到总表 `判分口径` 的某一句话上。** 写不出出处的，`credit` 只能是 `na`——不许「凭印象给分」。
6. **两个率都要给，且定义写死。** `judged_rate = (hit + miss) / total`（**可判率**，`na` 留在分母里，因为它是覆盖率的一部分）；`hit_rate = hit / (hit + miss)`（**判对率**，算不出就别给，不许拿可判率冒充）。只报一个率不报另一个，是本项目栽过的坑（§11-A5 同型：报「全过」不说分母）。

## 4. 判定口径（T00 定，你可以拿证据反驳，但不许默默改）

### 4.1 判定优先级（按顺序，前一步能定就不进下一步）

| 序 | 检查 | 依据 | 定了就 |
|---|---|---|---|
| 1 | 该点是否 `home=none`（模型没写） | 对齐表只 7 题有；其余题按「`by` 为空且无候选步」判 | `miss` |
| 2 | 候选步的 L1/L2 结论 | `run_answer` 写入的 `checks` | `pass`→hit 候选；`fail`→miss 候选；`na`→进第 3 步 |
| 3 | 式子/判据的结构等价 | 见 §4.2 | hit / miss |
| 4 | 结果规范（单位、方向、有效数字、舍根） | 总表 `判分口径` 里写「未写单位」「未舍去」的 | 可把 hit 降为 miss |
| 5 | 仍定不了 | — | `na` |

### 4.2 等价判定的铁律

**只认物理等价，不认数值巧合。** 判据是「换一组参数，两式是否还给同一个答案」：

- 认：两边同除/同乘、移项、代入消元、相对速度等大反向（一维弹性碰撞的等价判据）。
- **不认**：只因本题参数恰好同值而成立的等式。**反例已定**：`B-20-S09` 的 `4t` 与 `6t+2t`，只在 `M=m=1` 时同值，换一组质量给不同答案（裁定书 §三）。
- **测试要求**：这条必须用**一个 `M≠m` 的变体题**来测，**不许拿原题测**——原题测不出来。

### 4.3 `discussion` 步的特殊处理（40 步，占 18%）

实测（本卡作者，19:28，对 27 份金标统计）：`kind` 分布 `equation 112 / discussion 40 / judgment 35 / value 30 / critical 6`。**全部 40 个 `discussion` 步都有 `equation` 锚点、全部没有 `criterion`**——`equation` 与 `criterion` 双空的「无锚点步」在 27 份里**一个都没出现**（Schema 层的风险没有落地，这是好消息）。

**但有个真问题**：这 40 步的锚点是式子，而 `判分口径` 考核的常常是**结果规范**（单位、方向、有效数字、舍根）。例：`A-02-S12`「`v_A′=v₀`，另一解舍去」——式子对，但学生**没舍**另一解，按口径该扣。**只比式子的判分器会把这类判成 hit。**

**处置（写死）**：`discussion` 步必须**同时**过式子等价 + 结果规范两项，缺一项不得 hit。结果规范检查读 `value.unit` / `value.direction` / `value.exact` 与 `判分口径` 里的关键词（「单位」「方向」「有效数字」「舍去」「舍根」）。

### 4.4 `merged` 只 1 个点，但必须写对

全表唯一：`A-02-S08`，同时承载 `A-02-S06`（2 分）与 `A-02-S07`。风险落在 S06：模型给了「质心匀速」、没给「相对简谐」，2 分里可能只拿 1，而与 S07 共用一步，**机械分摊判不出**。
处置：`score_range=[0,2]` + `uncertain=true` + `basis` 写清「哪一句给了、哪一句没给」。**不许对半分**，也不许因为它不确定就整点判 0。

> 回执 §6 问「S2 拿金标步当每点 reference 算不算越界」。**不算**——卡 §2 明文允许读 `steps[]`，只禁 `grading`。但必须限死用途：
> ① **定位**：这点在说什么（对应金标哪一步）；② **对照**：模型那步是否在说同一件事；③ **结果规范核对**（单位/方向/有效数字/舍根）。
> **不得作 hit 的充分条件。** 每条的 `basis` 必须引总表 `判分口径` 的原句；**口径没写的要求，不许从金标反推**（反推 = 照参考答案判卷，是 §11 九个坑的同型）；若某点只能靠「像金标」才定得下来 → `credit=na`，不许 hit。
> 依据：S2 自带的反例 `½a₂t − L/6` 打的就是「长得像」；金标是参考答案，不是评分标准。

> **裁定 D3（T00，19:52，`home` 一致率为闸、`by` 精确匹配只作诊断）**
> 两个数都报，**闸只认 `home` 四分类一致率**（64 点，≥90%，与上面闸一致）；`by` 集合 exact match 列为诊断列，**不单独当闸**。
> 理由：free 模式合法拆分/合并步骤，用 `by` 精确匹配当闸，会把「学生解法不同」记成「判分器错」。卡的闸原文就是 `home`，不改。
> 附加一条：`home` 一致但 `by` 完全不同的点，**必须逐条看 `basis`**——防「数对了理由错」。两个数不许挑好看的只报一个。

### S3 等价形式 + 结构隐含判定

- 3 条等价（`A-02-S02` / `S14` / `S18`）+ 3 处结构隐含（`B-09-S05` / `A-10-S06` / `B-20-S05`）
- **闸**：6 条全对；且 `M≠m` 变体题上 `4t` vs `6t+2t` **判不同**（这条比前一条更重要）

### S4 `merged` 与全量核对

- `A-02-S08`：区间 + uncertain，不许对半
- 全量：7 题 × 66 点逐点 diff 人工对齐表 → `判分器/核对表_7题66点.md`
- **闸**：① 66 点逐点有结论（含 `na`，不许留空）；② 与人工基线 64.5/66 的每一处差异都有裁定（是人工错、还是判分器错，**不许「调参调到数字一样」**）；③ `judged_rate` 与 `hit_rate` 都写明；④ 按 D1 检查降级开关——`judged_rate` < 70% 时按 C 形态交付并明示原因分布，**不许宣称 S4 通过**

> **S4 的验收红线**：判分器给出的 hit 数**不等于** 64.5 时，不许改判分器去凑。要么证明人工错，要么承认自己错。凑数就是 §11 那九条坑的第十条。

> **第二条红线（D1 带来的）**：不许为了让 `judged_rate` 过 70% 而把 `na` 改判成 `miss`。`na` 是因为**我们判不了**，改成 `miss` 等于把自己的盲区记成学生的失分——这比数字难看严重得多。
