### 3.2 B-20 那 2 个 `L2 fail` 是验证器的假 fail（核心）

两处：`B-20-S11`（equation）与 `B-20-S17`（value），报错文本相同：

```
加减项量纲不一致：L 为 m；-2*t**2 为 s^2     （E-12）
```

模型写的是 `L - Rational(1,2)*(6-2)*t**2`。**这在物理上是对的**：

- 6 与 2 是图乙 a 轴的两段读数，单位 **m/s²**（该题对齐说明里就用 `Δa/ΔF=(6-2)/(8-4)=1/M` 算过斜率）；
- `(6-2)=4 m/s²`，`½·4·t² = 2t²`，量纲 **m**，与 `L` 一致。

那验证器为什么判 s²？根因在 `验证器/units.py:_walk_add`：

```python
# 纯数字字面量（不含符号）不参与量纲比较
if t.is_number and not t.free_symbols:
    continue
```

- `v0 - 4`：`4` 是纯数字 → 跳过 → 通过 ✔（注释里「规则 2」说的就是这种）
- `2*t**2`：含符号 `t` → 参与比较，而系数 `2` 被当作**无量纲** → `t²` 只剩 s² → 判 fail ✗

**所以我实测复现了三种写法**：

| 输入 | 结果 |
|---|---|
| `v0-4` | 通过（m/s） |
| `L-2*t**2` | **DimError** |
| `L-Rational(1,2)*(6-2)*t**2` | **DimError** |

规则 2 只覆盖「整项是数字」，没覆盖「数字系数 × 符号」。**sympy 串里一旦把单位算进系数，单位信息就永久丢失**，验证器无从知道那个 2 是 m/s²。

**影响面**：凡是模型「先把系数算出来再写式子」的步，都会被判 fail。本批 7 题只中了 2 步，不代表范围小——只代表这批模型偏爱保留符号。换个更爱先算系数的模型，这类假 fail 会成片出现，而判分器一旦上线，它们会被当成「模型算错」扣分。

**处置**：见 §5（已裁并落地）。
