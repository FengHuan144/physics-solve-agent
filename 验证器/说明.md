## 2. 两种模式都做，合并成一条 check

高中物理解题是「先列一堆方程、最后联立」，要求每步都能解出来等于把正常步骤判死。

| 模式 | 判什么 | 能抓 | 判不了 |
|---|---|---|---|
| `per_step` | 只用**前序**步骤的 `value` 当已知，解本步方程，与本步值比 | E-10，能定位到步 | 列方程步（无 value）；依赖后序量的步 |
| `chain` | 全题所有已知一起代入，看方程组是否相容；再试「只改一个值能否让全题残差归零」 | E-10、跨步矛盾、部分 E-04 | 方程本身建错（L5）；欠定步 |

合并规则（写死在 `l1_deduce.merge`）：

- 任一模式 fail → **fail**（错误码取更具体的：E-10 优先于 E-04）
- 否则任一模式 pass → **pass**
- 否则 → **na**
- `degraded` → **skipped**

两模式结论打架（一 pass 一 fail，或错误码不同）时**按 fail 报**，detail 末尾标「需人工复核」——
不静默挑一个看起来顺的。

## 3. `status` 四值怎么用（写死，不许自创）

| 情形 | status | detail 写法 |
|---|---|---|
| 方程相容、残差 0 | `pass` | `回代残差 0（per_step）` |
| 方程矛盾（无解） | `fail` | `本步方程对本步符号无解（方程自相矛盾）` / chain 归因失败时写 `改正任一单步数值都不能归零` |
| 欠定（方程数 < 未知数） | `na` | `欠定：3 未知 / 1 方程（chain 可解，本步不判）` |
| 该步 `parse_status=degraded` | `skipped` | `解析降级，本层停用（degraded 不计入 fail）` |
| 该步是 `judgment/discussion/critical`，**无方程** | `na` | `非方程步` —— **本 Schema 里每步都 `required: equation`，这一支实际走不到**；此类步由下一行（无 value）承接 |
| 本步无 value，方程只有一个自由符号 | `na` | `本步无 value：方程可直接解出 X，但本步没给值，无从比对` |
| 上游数据错误（等号/白名单外符号/单位不是 pint 串） | `na` | `data_error(<kind>): …` |
| 方程化简为 0（`sympy="0"`、`x-x`） | `na` | `方程化简为 0，无可比两侧（与 L2 同口径）` |

`skipped` 是 Schema 里有专门含义的值（因 degraded 停用该层），**没拿它当 na 用**。
`data_error` 的步不进 pass/fail 分母（否则一行坏数据会把通过率算低），也不冒充 fail。

### 多层同报的去重（§10-4 已定）

方程**本身**量纲不符时，同一步 L1 算出的残差是同一个病灶的症状，不是第二个错。
这种步 L1 降为 `na`，detail 写：

```
不重复计数：根因见 L2/E-12（方程两侧量纲不符）。本步 L1 原判 E-10：<原判据>
```

原判据留在 detail 里，去重决定可复查。**只对「方程两侧比较」的 E-12 生效**：
`value.unit` 的 E-11 / E-12 不触发——那时方程可能完全正确，而数值是真错的，
吞掉 L1 就会漏掉一个独立缺陷（C11 专门钉这条）。

## 4. L2 只保证「单位类型对」，不保证「单位数值对」

题干给 `L = 5 cm`，模型写成 `L = 5 m` 代入：

- 量纲：两边都是长度 → **L2 判 pass**（L2 的职责就只有量纲，这条边界没变）
- 数值：差 100 倍 → **判在 L1**，因为 L1 读值时会先按 `unit` 折成 SI
  （`L` 折成 0.05 m，与模型写的 5 m 不符 → 残差非 0）

v1.3 之前这句话是错的：原文写「只有 L1 的残差能抓」，可 L1 当时也直接读
`value.number`、根本不看 `value.unit`，所以 `3 cm/s^2` 与 `3 m/s^2` 在两层眼里一模一样，
100 倍差**没有任何一层能标记**（审核方 §2.3 抓的就是这个）。现在 L1 统一走
`units.to_si()`，这条边界才真的成立。

**仍然抓不到的那一半**：该量若没有出现在任何可回代的式子里（本步无 value、
或符号不在方程里），换算再好也没有对照量 → 只能是 `na`。这是数据问题，不是换算问题。

| # | 取舍 | 后果 |
|---|---|---|
| 1 | 加减式里的**数字字面量**按 SI 值处理，不参与量纲比较 | `v0 - 4` 不判 E-12；代价是 `m*v**2 - 5` 这类错也抓不到 |
| 2 | 字面零忽略 | `Fnet - 0` 不判 E-12（牛顿方程里「合力为零」是常态） |

| 5 | 结构性问题统一记 **E-04** | E-04 / E-06 / E-13 在 L1 上都是「残差非 0」，无法只靠式子区分；detail 写明三者皆可能 |
| 6 | 方程级 E-12 与 L1 失败同报时，L1 降 `na`（§10-4） | 失败只计一次；`value.unit` 的问题不去重，两条都留 |
| 7 | 非数值条件（`M=m`、`θ` 无 value）不建模 | 相关步只能 na |
| 8 | `degraded` 步的 `value` 仍当已知用 | 只停用它的「方程」；否则一处降级会连锁把后续步拖成 na |
| 9 | 不修上游数据 | 等号 / 白名单外符号 / 单位不是 pint 串 → `data_error` + `na`，不 split、不补符号 |
| 10 | chain 归因复杂度 O(n²) | 按**题**跑（每题 ≤15 步）没问题；别拿它跑整卷 223 步 |
| 11 | 方程化简为 0（`sympy="0"`、`x-x`）→ L1 判 `na` | 空方程**不是算错**，是没有可比两侧；与 L2 同措辞。判 fail 会把「没给东西」算成「给错了」 |
| 12 | 非 SI 单位一律**先折 SI 再判**（`3 cm/s^2` = `0.03 m/s^2`） | 换算失败（如 `-`、`N-m` 或 offset 单位）→ `data_error` + 本步 `na`，**绝不静默当 SI**；`exact` 字段是 sympy 串，不参与换算 |
| 13 | 降级步的值仍当已知用，但**折不成 SI 的值不算** | 已知量单位坏了会连带把后续步判 `na`，不判 fail——宁可少判，不判错 |
| 14 | **加减项含整数数值系数且量纲不符 → 判 `na` 不判 `fail`**（2026-11-25 新增） | 见下节。只有**整数**系数才放过；`½`、`1/6` 这类公式系数照判 fail（否则回归用例 C03 当场破） |

### 14 的来由与边界（2026-11-25，用户「按你的来」）

**现象**：B-20 的模型写 `L - Rational(1,2)*(6-2)*t**2`。`6`/`2` 是 a 轴读数（m/s²），
`½·4·t² = 2t²` 量纲是 **m**，与 `L` 一致，**式子是对的**。但 sympy 串里单位已并入系数 2，
`_walk_add` 只看到 `(-2*t**2)` 的量纲 `s²`，判 E-12——**验证器冤枉了它**。

**处置两侧**：

| 侧 | 做法 | 文件 |
|---|---|---|
| 生成侧（根因） | `equation.sympy` 不许把单位算进系数：写 `Rational(1,2)*acc*t**2`，不写 `2*t**2` | `schema/字段清单.md`、`子agent/T08f_*.agent.md` 硬纪律 9 |
| 判据侧（兜底） | 不符项含**整数**系数时抛 `DimUndecidable` → L2 落 `na`，detail 写「量纲不可判定」，**不置** `equation_broken` | `units.DimUndecidable`、`l2_dimension.analyze`、`tests/test_l2_coeff.py`（10 条） |

**为什么必须收窄到整数**：初版写成「任何 ≠1 的系数都放过」，回归用例 C03
（`Rational(1,2)*a2*t - L/6`，真错：m/s vs m）**当场判 na**，11/11 掉到 10/11。
整数与非整数的区别有物理含义：**读数代入后的系数通常是整数**（a=4 → ½·4=2），
而 `½`、`1/6` 是公式自带的，单位还留在后面的符号里。收窄后 C03 恢复 fail。

**残留盲区（明写）**：`L - 3.5*t**2`（a=7 m/s²）系数非整数，仍会被判 fail。
所以这条是兜底，不是许可——新写的一律守生成侧那条。

**实测影响面**：7 题双跑，只有 B-20 变了（L2 `pass6/fail2/na9` → `pass6/fail0/na11`），
其余 6 题逐题零变化（`tests/test_l2_coeff.py` t10 钉住）。

## 11. L4 条件一致层（`l4_condition.py`，2026-11-25 13:20）

### 11.1 规则 A：符号从哪来的

合法来源（按卡 §1，**多加了第 5 类**，理由见 §11.2）：

```
① situation.given[].symbol            题干给出的量（含 value 为 null 的非数值条件）
② situation.objects[].mass_symbol     物体质量 m、M、m1…
③ 前序步的定义                        有数值的 value.symbol，或此前某步以方程定义过的量
④ 通用常量 g                          只有 g，不扩
```

逐步判：

| 情形 | status | detail / 后果 |
|---|---|---|
| 符号全在 ①~⑤ ∪ ③ | pass | `符号全部有来源` |

| 一步多出 **≥2** 个无来源符号 | **fail E-04** | 一个方程只能定义一个量，其余视为凭空条件 |

### 11.2 与卡文的一处偏差：加了 ⑤ targets

卡列 4 类来源，我加了 `situation.targets[].quantity`。理由：题目要求求 `v0`，
解它必然要引入 `v0`——不引入反而是漏答（E-08）。这不是放宽判据，
是把「题干要求求的量」和「凭空给的量」分开。若你认为应当严格按 4 类，
删掉 `_global_sources` 里 `targ` 一行即可，代价是每个目标量首次出现都会被当成新符号。

### 11.3 规则 B：小问归属

小问号来自 `采分点总表` 的 `point_id → 小问` 列（Schema 里没有这个字段，这是唯一数据源）。

| 情形 | status | 码 |

| 第 (n) 问的步引用了只在第 (m>n) 问才定义的量 | fail | `E-14` 状态量取错时刻 |

首步与末步没有两侧邻居，`_sub_outlier` 直接不判——宁可漏，不许冤。

### 11.4 错误码：优先级与缺口

一步同时命中多条时只出一条 check，码取 `E-03 > E-14 > E-04`（归属是根因，症状排后），

### 11.5 能抓 / 抓不到

### 11.6 规则 C 为什么只报缺口

`E-09 边界/起始位置误判`（用 20l 与管长 20l 比较，盘起始距口 l）要判，
必须先知道「这一段的位移从哪个参照物起算」。Schema 里 `process_segments` 只有
中文 `start` / `end` 文本，没有「分段 ↔ 步」的映射字段，也没有参照物字段。
硬做就得靠字符串匹配中文，那已经不是规则。

所以 C 的产物是**一条题级 na 说明**，写清缺哪个字段，而不是每步硬判一个 pass。
