## R1 primary 怎么选

**查了什么**：口径 1 原文是「primary 取与金标 `value` 同量同值的那一步」。但 v1 里 `A-08-S06`（gold `kind=value`，`a2=5`）的 primary 是 `A-08-S07`，那步 `value=null`；`A-10-S06`（gold 带 `value: v0`）的 primary 是 `A-10-S07`，同样 `value=null`。

**裁定**：保留「一个点一个 primary」的框架（A 案），因为 B（顺序优先）会让空式子当命中——`B-20-S06` 口径是「只解出部分量本步 0 分」，四个量拆成四步，顺序第一步恰恰只给了 `M+m`；C（取消 primary）会让判分器失去「这个点有没有值落下来」的信号。
**同时把依据改成可操作的一条**：

> primary = 承载该点**不可替代证据**的那一步。值点在值上；判断点在判断句上；**混合点（金标里 value 与判断句同处一步）在口径 0 分条件所考核的那一块上**；其余承载步记 split。

这条不是给 R4 开的后门——它是 v1 实际已经在用的规则（上面那 2 处就是证据），只是文字写窄了。改文字，不改数据。

**数字后果**：0。

## R2 `A-02-S08` 标 merged，断言放宽

**查了什么**：模型 `A-02-S08` 原文一句：「第一次碰撞中质心做匀速运动……故 t=t₀ 时质心位移为 v₀t₀；质心位移又等于 A、B 位移的加权平均，同时 A 的位移为 9/25 v₀t₀」，`equation` 里就是 `(m s_A + 5 m s_B)/(6m) − v₀t₀ + s_A − 9/25 v₀t₀`。金标 `A-02-S06`（判断，2 分，口径「只说面积不解释给 1 分」）与 `A-02-S07`（`m s_A+5m s_B=6m v₀t₀`，solve `s_B`）**登记的是同一条方程**——这是金标侧的重叠，不是模型拆不开。

**裁定 B**：标 `merged`，`point_ids=[A-02-S06, A-02-S07]`。
- 判据：删掉这一步的方程，**两个点同时失去证据** → 真合并。反过来，`B-12-S01`（判定「看作整体」+ 方程）删掉方程后判定句仍在、只塌 S02 → 不是合并。这就是新判据与旧「有可分辨句子就不算」的分界。
- 断言改：`merged 步 ≥2 个 home=merged 点` → **`每个 merged 步至多承载的点里，至少 1 个 home=merged`**。理由：原断言要求「一步要撑起两个点都失去独立步」，而 S07 另有 S09 独立给值，这个要求本身错——真合并的危险是「**有一个点**的部分对无处分摊」，不是「所有点都无处分摊」。

**数字后果（实跑后）**：p60→59、s40、m0→1；home 1:1 33→32、1:n 32、mg 0→1、none 1。
**这 1 个 merged 要写进首屏**：全表唯一，涉及 `A-02-S06`（2 分）——模型只给了「质心匀速」，没给「相对简谐」，2 分里可能只拿 1，而这一步同时扛着 S07 的方程，机械分摊无法判断该扣 1 还是 0。

## R3 三条「物理等价」——认，但要分清三种性质

**查了什么**：三条都核过式子。模型给的确实不是同一式的移项/同除：

| 步 | 性质 | 为什么不能靠字面 |
|---|---|---|
| `A-02-S02` | **同解不同路**（碰后分离时刻 vs 共速时刻） | 换一组质量不同解；这里只是恰好解出 M=5m |
| `A-02-S14` | **等价比替代**（相对速度等大反向，一维弹性碰撞的等价判据） | 全式没有 ½mv²，字面匹配必 0 |
| `A-02-S18` | **合并式**（全程式，需先消去上滑式才等价） | 口径的采分关键「与上滑式符号相反」在这一步看不到 |

**裁定 A**：认命中，保留 `equiv_form=true`，note 里按上表写清是哪一种。
**不选 B 的理由**：物理都对，判写法不给分等于惩罚非标准解法；且 §5.1 五类里没有「写了但不算命中」的位置，选 B 得先造一个类别，代价比收益大。

**但要记死一件事**：这三条**只能靠判分器识别，不能靠字面**。所以它们是判分器的输入要求，不是对齐的遗留问题（见第四节）。

## R7 B-20 折点读数：不补点

**查了什么**：表 `B-20-S05`（2 分）只登记三条读数 `k₁=0.5、k₂=1、b₂=−2`，口径两条 0 分是「滑动段斜率当作 1/(M+m)」「截距符号取正」。折点纵坐标 `a=2` 不在任何一条里。模型读的是折点 `(4 N, 2 m/s²)`，用折点求 `M+m=2`、代入求 `μ=0.2`、高段斜率求 `M=1`。

**裁定**：不补。两条硬理由：
1. 采分点表的分数来自原卷，表里没这一条，补点就是凭空造分；
2. **和已出的分对不上**：首跑报告 B-20 是「9/10 点、**13/14 分**」。若 `B-20-S05` 判命中（2 分），B-20 按分变 **15/14**，超卷面——所以这 2 分不可能整份给出去。

**顺带查出一个对不上的地方（不属本次裁定，但必须记）**：对齐表说 `B-20-S05` 是 `none`（即 0 分），可报告只丢了 **1 分**。若 S05 真为 0，B-20 按分最多 12/14。**两份文件的失分点对不上**，要回查 `评测/T20/logs/run_*.json` 的逐点记录才能定：是报告少丢了分，还是 S05 实际拿到了 1 分（部分命中，那对齐表的 `none` 就该改成「命中 1 条读数、缺 2 条」）。**本次不动分，只登记。**

**代价明写**：模型信息量上确实读出了同样三件事（M、M+m、μ），判 0 是**表的登记口径**所致，不是模型算错。所以 `none` 的 gap 必须原样保留这段，判分器不许把它当「模型漏读」处理。
