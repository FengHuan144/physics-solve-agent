## R1 primary 怎么选

**问题**：金标一个 value 被模型拆成「方程段 + 代入段」时，哪一步算 primary。v1 取「与金标 value 同量同值」那步，其余 split（40 步）。

**三个备选**：
- A. 维持（值落哪步哪步 primary）
- B. 取第一个承载该点的步（顺序优先）
- C. 取消 primary/split 之分，统一记 hit
- D. 一个点允许多 primary（凡给出 value 里某个量的步都标）

**数字后果**：A→B/D 都只改 primary-split 归属，**home 分布不动**（home 只看 `by` 非空）。但 B/D 要重判 101 步，我给不出机械值。
C 会让步分类从 6 类降到 5 类，§10 断言 3 的「primary/split 单点」直接失效，判分器失去「该点有没有值」的信号。

**建议 A**。依据：`B-20-S06` 口径是「只解出部分量本步 0 分」，而它被拆 4 步——只有把三个量凑齐那步才算数，顺序优先会把空式子当命中。**注意 R1 与 R4 联动**：若选 C 或 D，R4 就不成问题；若选 A，R4 必须维持现状，否则该点无 primary。

## R2 `merged` 与 §10.2 断言互斥

**问题**：`A-02-S08` 只给一个方程 `m·s_A+5m·s_B=6m·v₀t₀`，同时充当金标 S06（质心判据）与 S07（解 s_B）的证据。按 §5.1「一步同时承载 ≥2 个点且没给分开的式子」→ 字面就是 `merged`。但 §10.2 要求 merged 步撑起 ≥2 个 `home=merged` 点；S07 另有 S09 独立给值，只能是 `1:n`，于是 1 步 → 1 点，断言必挂。

**数字后果（实算）**：
- A 现状：p60+s40+m0｜1:1 33 / 1:n 32 / mg 0 / none 1｜断言全过
- B 标 merged：p59+s40+**m1**｜1:1 32 / 1:n 32 / **mg 1** / none 1｜**§10.2 断言失败**（1×2=2 > 1）
- C 顺带把 S07 也改 home=merged：数字同 B，但 S07 实际有独立步，属造假

**建议 B**，同时把断言改成「每个 merged 步承载的点里，**至少 1 个** home=merged」。依据：merged 是判分器唯一真怕的形态，若这类形状被断言逼着不敢报，merged 这格永远是 0，等于白设。**改的是卡面 §10.2 + 脚本第 574 行**，需你授权。
