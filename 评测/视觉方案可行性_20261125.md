## 1. 实测（两次请求，都是真实 API 调用）

### 1.1 第一次：1×1 像素图 → 失败，但失败原因很关键

```json
HTTP 400
{"error":{"message":".messages[0].content[1]: You have uploaded an invalid image.
The image data is corrupted or truncated and could not be decoded."}}
```

**这条错误说明接口接受 `image_url` 字段并尝试解码**。如果模型不支持视觉，报的会是「不支持的 content type」或直接忽略该 part。所以第一次虽然失败，但排除了「完全不支持」这个可能。

### 1.2 第二次：200×120 折线图（模拟 a–F 双段折线）→ 成功

图片内容：白底，横轴 F、纵轴 a，红色两段折线。第一段 (20,100)→(90,50)，第二段 (90,50)→(180,30)。
数学上第一段斜率 50/70≈0.71，第二段 20/90≈0.22。

```
HTTP 200
模型返回：两段折线；第一段斜率更大。
usage: prompt_tokens 225 / completion_tokens 10
```

**判定正确**：段数对、斜率大小关系对。

### 1.3 实测的边界（必须声明的空白）

| 项 | 状态 |
|---|---|
| 单张图 + 中文文字提问 | 已验 |
| 折线图读数（斜率大小定序） | 已验 |
| **精确数值读数**（如「读出截距是 −2 m/s²」） | **未验** |
| 多图输入 | 未验 |
| 大尺寸图 / 复杂几何图 | 未验 |
| 图内中文标注识别 | 未验 |

**所以现在只能说「视觉通道通」，不能说「B-20 一定读得对」。** 后者要拿真图跑一次才知道。

## 2. 走视觉方案后，B-20 该怎么记（N2 的落地口径）

### 2.1 不要「整题剔除」，记 `input_missing`

两个做法都让 B-20 退出准确率分母，但信息量差一个量级：

| 做法 | B-20 三变体的记录 | 能回答的问题 |
|---|---|---|
| 整题剔除（原方案 B） | 从表里删掉 3 行 | 无。只是「不算了」 |
| **记 `input_missing`** | 保留 3 行，`verdict=input_missing`，`failure_type=input_missing` | **模型会不会识别「我看不见图」** |

后者正是 T07 任务卡 R12 的原意（「缺输入判 `undecidable`+`input_missing`，不许记 `wrong`」），也是 `report.md` §10-3 那条结论的落点：**0/66 主动承认缺图**。

按此口径，B-20 贡献的不是「答错」，而是一个独立指标：**缺输入检测率 0/3**。

### 2.2 三个变体的数字会变成

| 变体 | 现状（含 B-20） | 改记 `input_missing` 后 |
|---|---|---|
| v1 | 20/22 = 90.9% | **19/21 = 90.5%** |
| v2 | 21/22 = 95.5% | **20/21 = 95.2%** |
| v3 | 19/22 = 86.4% | **19/21 = 90.5%** |

与 `report.md` §9.1「按口径 B 剔除」的数字完全一致——**说明这套口径不是新发明，只是把「剔除」换成了有语义的标签**。

### 2.3 一个副作用要一并承认

v3 从 86.4% 升到 90.5%，**与 v1 持平**。所以 §10-4 那句「v3 更差」要降级为「v3 不优于 v2、与 v1 持平」。这不是粉饰——原因就是 B-20 在 v3 里恰好是唯一 `wrong` 之外的最大失分点。

## 3. 视觉方案对 N4（图数据源契约）的影响：**反而简化了**

`schema/图数据源缺口评估.md` 给的方案 1 要加 `given[].source` 或 `figures[].provides[]`，代价是升 1.2 + 8 份样例重跑。

**但如果走视觉方案，这些字段都不需要**：

- 模型直接看图，图读数不需要写成 `given`——它不在题干里，本来就不该在 `given` 里；
- 「模型读错图」的表现就是答案数值错，L1 回代自然判 fail，**不需要额外字段去标记「这个量来自图」**；
- 真正需要新增的只有一个**评测层的元数据**：这条样本的输入是否含图（`input_modality: text | text+figure`）——它属于评测集，不属于 `answer.schema.json`。

**结论**：视觉方案把「契约缺口」降级为「评测集元数据缺失」。这是它比方案 1 更优的地方，比单纯「短期不改」也更有出路。

## 4. 三个前提（缺一不可，按阻塞程度排）

| # | 前提 | 现状 | 谁来做 |
|---|---|---|---|
| 1 | **B-20 的 a–F 原图** | 工作区 **0 张图** | 从 `原始资料/` 的 doc/pdf 提取，或按 T05a 的检索式重新获取（与 A-05 同样路子） |
| 2 | `run.py` 支持多模态 | 现在是 `messages[0].content` 纯字符串 | 改 `call_once` 接受 `content` 数组；raw 里要存「本样本输入含图」标记，否则事后无法分辨 |
| 3 | 口径分层 | 66 条是纯文本口径 | 视觉结果单独成表，**不与 66 条合并算准确率**；合并即失去可比性 |

### 为什么第 3 条是硬约束

66 条里 21 题是纯文本、B-20 是图数据源。若把 B-20 换成带图输入后仍并进同一张表，等于「一半样本给图、一半不给图」算出一个总准确率——这个数没有解释力。要么全给图（成本高），要么分表（成本低）。

## 6. 一句话提醒

本次实测只证明了「模型能从一张干净折线图上分出斜率大小」。**从「能分辨斜率大小」到「能读出 −2 m/s² 的截距并代进 μmg/M」之间，还隔着一次真图探针。** 建议先在单题上验，再谈改管线——不要在未验之前把 T12b 写成「已解决」。
