## 3. 为什么驳回"统一 40,000"

B-15 的两次调用暴露了方向：

```
10:15  max_tokens=32768  finish=length  tok=382+32768   ← 截断
10:27  max_tokens=65536  finish=stop    tok=382+55748   ← 模型要 55.7k
```

预算从 32,768 抬到 65,536，答案没变好（本来也没坏），支出翻倍。**预算不是上限，是"够用就花完"的额度**。正确做法是**按难度分档**（易 12k / 中 24k / 难 40k），并且截断只记账不重试。

## 4. 三条新做的实测（共 0.09 元）

以 B-12（9 步、纯文字、基线 8,242 out）为样本，三次同题调用：

| 配置 | out tok | 耗时 | 步数比 | 答案质量 |
|---|---:|---:|---:|---|
| 默认 | 8,242 | 39.7s | 1.67 | 三项全对 |
| `effort=low` | 10,985 | 78.6s | 1.67 | 三项全对，**但更贵** |
| `thinking=disabled` | **1,720** | **5.7s** | **1.11** | **答案摘要与自身步骤矛盾：摘要写 N₂=7 N，第 4 步算出 5 N** |

三条结论：

1. **`effort` 参数是死的**。传 `effort="banana"` 仍返回 200 —— 该字段被静默忽略。审计报告若建议走"降推理强度"的路，这条路不存在，别再试。
2. **思维可以关，代价是自洽性**。省 4.8 倍、快 7 倍，但模型在收尾汇总时会写错自己刚算出的数。1 题样本不足以定论，但足以否掉"用它当交付答案"。
3. **单次调用有 ±30% 噪声**。同一个 prompt（temp 0.2）两次跑出 8,242 / 10,985。任何"省了 20%"的说法都必须重复测才成立。

## 7. 裁定：无思维档封存（2026-11-25 17:06）

**判据先写死再跑**：A-08（纯文字最贵）、B-20（带图最难）两题须同时满足 E=0、步数比 ≤1.3、
一致性检查零报错、关键取值与金标一致；任一不满足即封存。

A-08 单题即触线，按判据封存，B-20 未再调用（省 1 次）。

| 指标 | 默认思维 | 无思维 |
|---|---|---|
| 输出 token | 22,525 | **3,612（省 6.2 倍）** |
| 步数 / 金标 11 | 19（1.73） | **23（2.09）** |
| Schema | E=1 W=12 | E=0 W=11 |
| 三个答案 | 30 N / 3.2 s / 95 J **全对** | 30 N / **1.5 s** / **36 J** |
| 一致性检查 | 无报错 | **2 条报错** |

决定性证据不是"错了两问"，而是**怎么错的**：第 11–22 步是一段 `v=2, -2, 1` 的周期性往返——
模型在两物体间反复碰撞、永不终止，最后直接跳到 Q=48。**没有草稿纸，它就不做搜索与剪枝**，
在难题上退化成循环。而 B-12（容易题）上它反而更像金标（10 步、1.11），所以这个档的表现
**随难度反向崩坏**——正好在最需要它的地方崩。

三条理由合成结论：

1. **收益与风险错位**：省 0.08 元/题，换来的是"难题上答案错、且错得不显眼"（E=0 仍通过）。
2. **不稳定性**：同档两题步数比 1.11 / 2.09；思维档七题 1.11–2.00 有明确上界。
3. **一致性**：2/2 无思维样本被新检查抓到摘要错，8/8 思维样本干净（含 B-20 的 `L=9/2` 分数写法）。

**处置**：`--no-think` 开关保留但加封存警示，只作对照，不进 prompt 矩阵、不计入能力测量。
`answer_consistency()` 保留（这是本次唯一净增的检查能力），已回测 8 份草稿零假阳性。
