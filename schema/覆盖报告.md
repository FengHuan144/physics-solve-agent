## 3. 四个缺口的结论

### 3.1 图即数据源（B-20 / A-02）— 方案 2 跑得通，但代价实测成立

B-20 的三条读数（0.5 kg⁻¹、1 kg⁻¹、−2 m/s²）**只存在于图乙**；A-02 的 B 碰前速度 1.2v₀、2t₀ 处 A 的 2v₀ **只在图 (b)**。两份样例用了两种不同写法，都过了校验：

| 题 | 写法 | 结果 | 代价 |
|---|---|---|---|
| B-20 | 读数写进 `given`，`value` 填数、`text` 前缀【图乙读出】 | E0 / **W1**（3 个新符号） | 读数成了「题干给定」，`stem_sha256` 锁不到 |
| A-02 | 读数写进 `given`，`value: null`、`text` 注明「图读出」 | E0 / **W0** | 数值以自由文本存在，机器读不到；指纹同样锁不到 |

**实测代价（探针 3）**：把 B-20 的 `k1` 从 0.5 改成 0.6，`validate_schema.py` 仍然 **E0/W1 通过**——它既比对 `given` 与 `nums`，也不比对 `checks.detail` 里的「k1=0.5」。**图读数写错，Schema 层查不出来。** 这就是方案 2「题干指纹与实际输入脱钩」的具体形状，不是推测。

方案 1 与 3 的代价见 `schema/图数据源缺口评估.md`；本卡不写它们的代码。

### 3.2 多解（A-02）— 结论：本例**不构成缺口**，但真并列解不可表达

A-02 的 S12 是本轮唯一「两根取舍」的点：`v_A′²+v₀v_A′−2v₀²＝0` 的两根 v₀ 与 −2v₀，后者与过程矛盾，舍去。**解集退化为单解**，`steps[].value` 单槽够用：`{symbol: v1, exact: "v0"}`，另一根写在 `l4` 与 `statement`，与判分口径（「两解都写未取舍也给 1 分」）一致。

**但探针 4 证实**：把 `value` 改成两条并列解的数组，直接 E（`is not of type 'object','null'`）。所以——

- 「两解选一、要写取舍理由」→ **能表达**（一解一 value + discussion 步写理由）；
- 「两解并列合法、各给分」→ **不能表达**，要加 `value.candidates[]` 之类，属改契约。

27 题里目前只有 A-02 一处舍根；**没有第二处「并列合法解」的实例**，所以第二种情形是**结构性缺口，不是已知需求**。

### 3.3 公式库 id（A-10）— **证伪**：「law_ids 指向 F-059~F-066」做不到

任务卡要求验「`law_ids` 能否指向万有引力那 8 条（F-059~F-066）」。**不能**：

- `law_ids` 的 pattern 是 `^L-\d{2}$`，只收 T10 的 12 条定律；
- 把 `F-059` 塞进去，探针 1 直接 E：`'F-059' does not match '^L-\\d{2}$'`；
- Schema 里**没有任何字段**承载 T09 的 74 条公式 id。这意味着 T09 的「覆盖率映射 223 步」完全在 Schema 之外——**公式引用不入库，跨表关联靠文件名和题号，不靠 JSON 字段**。

A-10 的 8 步全部挂 `L-07`（万有引力与天体运动），`L-06`（向心力）辅助，这一层是通的。

### 3.4 assumptions、小问标号、一步多式 — 三个小缺口

| 缺口 | 现象 | 证据 |
|---|---|---|
| `assumptions` 无约束力 | 把 A-10 的「均匀分布」「r>R 速度不变」两条关键假设**清空**，校验仍 E0/W4 通过 | 探针 2：`assumptions: []` 合法，Schema 对内容零要求 |
| 小问标号只能 `(\d+)` | B-20 原文是 `(1)`、`(2)(ⅰ)(ⅱ)`；Schema 的 `subquestions[].no` / `targets[].no` 只认 `^\(\d+\)$`，**写不进罗马数字** | B-20 样例把三部分平铺成 `(1)(2)(3)`（4+4+6＝14），`text` 里标「原文第 (2) 问 (ⅰ)」 |
| 一步多式 / 多结果只有一个槽 | B-20-S05 有 3 条读数、S06 有 3 个结果、S09 有 2 条守恒式；`equation` 与 `value` 都是单槽 | 用「残差和＝0」并入 `equation`（弱形式），`value` 只登记一个，其余进 `statement`/`l4` |

这三条都不影响本轮 E0，但会影响下游「逐步比对」的粒度：**模型写对第二式而第一式错时，单槽无法分辨**。

# 9. Schema 1.2 补记（T08d，2026-11-25 15:23）：四个缺陷的「改前 → 改后」证据

四个缺陷一次清算。**改前**的证据来自本文件 §3.1 / §5 与 T08d 任务卡 §1 的实测；**改后**的证据全部是本节实跑的原始输出，不是转述。

## 9.1 缺陷 ① 图读数伪装成「题干给定」

| | 形状 | 证据 |
|---|---|---|
| 改前 | B-20 的 k1/k2/b2 写在 `given`，`stem_sha256` 只锁 `stem_text` | §3.1 探针 3：把 k1 从 0.5 改成 0.6，**仍然 E0/W1 通过**（既查不出、指纹也不变） |
| 改后 | 三条读数进 `figures[fig_no=2].provides`（带 `read_from` 定位句），`given` 同符号项标 `source:"figure"`，新增 `question.input_sha256` | 同一扰动现在报 **2 项 E** |

```
[E] R11        图读数来源对不上：k1：given 记 0.5，provides 记 [0.6]
[E] R12        input_sha256 失配：文件记 e321e934a34129c5…，按当前 stem_text+provides
               重算应为 0b55bea226bbec5a… —— 图读数被改过，或改完没有重算指纹
失败：2 项 E，0 项 W → 退出 1
```

- 两道闸各自独立：R11 抓「given 与 provides 打架」，R12 抓「provides 被改但指纹没重算」。只改其中一处都过不了。
- A-02 是符号读数（1.2v₀ / 2v₀ / 0.8v₀），`provides.value` 记 `null`、符号表达写 `text` —— 该题的指纹同样由 `text` 覆盖：改「1.2v₀」为「1.3v₀」，`input_sha256` 必变。
- `stem_sha256` **保留未动**，两指纹并存（其余工具仍在用 stem_sha256）。

## 9.2 缺陷 ② 整题 `L1: pass` 与步级 `na` 矛盾

| | B-09 | B-12 |
|---|---|---|
| 改前（1.1 样例） | 整题 `L1: pass`，步级 1 步 na（S05） | 整题 `L1: pass`，步级 2 步 na（S01、S03） |
| 改后（1.2 重生成） | 整题 `L1: na`，步级 na = 1（B-09-S05） | 整题 `L1: na`，步级 na = 2（B-12-S01、S03） |

反推口径：`fail > na > skipped > pass`，全 pass 才 pass。手工把整题写回 pass，现在报 E：

```
[E] R13        整题层与步级矛盾：L1 整题=pass / 步级反推=na
               （整题层必须按「有 fail 记 fail、有 na 记 na、全 pass 才 pass」反推）
失败：1 项 E，0 项 W → 退出 1
```

其余 5 份的整题 L1 与改前一致（A-08 pass、B-20 pass、A-02/A-10/B-02 na），说明这一条只纠正了矛盾的两份，没有连带改别的。

## 9.3 缺陷 ③ L4 边界一致性判不了

| | 改前 | 改后 |
|---|---|---|
| 过程分段 | 只有 `no/name/start/end`，无稳定 id | 28 段全部有 `segment_id`（`SEG-01` 起）+ `boundary_reference`（如「以碰前瞬间为起点」「以桌面为 h=0」） |
| 步 → 分段 | 无映射 | 62/66 步带 `segment_id`；4 步跨段留空（A-02-S15、B-02-S04、B-09-S05、B-09-S07），字段可选，不硬凑 |
| 校验 | `l4_condition.py` 只能报 `boundary_na` | R14 查重 + 查悬空 |

```
[E] R14        steps[].segment_id 悬空（无对应过程分段）：['A-08-S01→SEG-99']
失败：1 项 E，0 项 W → 退出 1
```

> 边界：**本卡没动 `l4_condition.py` 的判定逻辑**，只把 L4 需要的两个输入补齐。L4 拿它们做什么，另开卡。

## 9.4 缺陷 ④ `equation` 必填 → 判断步被迫伪装成方程步

| | 改前 | 改后 |
|---|---|---|
| 字段 | `step.required` 含 `equation`；`definitions.equation` 四字段全 required 不可 null | `required` 删 `equation`；`equation: oneOf[null, equation]`；新增 `criterion`（expr/expected/comparator/text 四项必填） |
| 数据 | 66 步**无 equation 的 0 步**；judgment 14 / critical 2 / discussion 10 全部背着式子 | `equation=null` 的 **13 步**（11 judgment + 2 critical），全部带 criterion；kind 分布 judgment 11 / equation 29 / value 22 / discussion 2 / critical 2 |
| 页面 | 判断步的叉打在式子上（原型分支永不触发） | 判断步无 equation 单元，叉打在 `statement` 上（实测叉宽 758 / 文字宽 746） |

**24 处步改动的逐条清单见 `CHANGELOG.md` §1.2「24 处步改动逐条」。** 校验侧规则：

```
kind ∈ {judgment, critical}  →  equation 必须 null  且  criterion 必须存在
kind ∈ {equation, value}     →  equation 必须非 null 且  criterion 必须不存在
discussion                   →  不强制（可只有 equation，也可只有 criterion）
两条同时违反 → 一个 E，不降级为 W
```

`criterion.text` 另设占位词检查：含「同上 / 见式 / 见上式 / 如前 / 略」直接 E —— 判据必须能独立读懂。
