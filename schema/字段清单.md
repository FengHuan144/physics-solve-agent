# 字段清单 · 给 D10 线框

> 配套 `schema/answer.schema.json` v1.0（draft-07）。只列「界面必须显示的字段」，不画布局。
> 三屏名取自方案 §08：① 单题诊断工作台 ② 异常队列 ③ 评测报告。

---

## 0. 与方案 v1.2 的差异（先看这条，否则下面全读错）

**L1/L2 的定义在材料里有冲突，本 Schema 以「错误码枚举」表为准。**

| 材料 | 写法 | 状态 |
|---|---|---|
| 方案 PDF §05 指标表 | 「量纲通过率 **L1**」「回代通过率 **L2**」 | 用反 |
| 方案 PDF §08 线框 | 「**L1 量纲** 通过 / **L2 回代** 失败」 | 用反 |
| `原始资料/agent.md` §2.2 | 「L1 计算 / L2 量纲」 | 一致 |
| **采分点表 v2「错误码枚举」检测层列** | E-10 代入代数错→**L1**；E-11 单位缺失→**L2**；E-12 量纲不符→**L2** | **采用** |

锁定口径（`validation.layers` 的键）：

```
L1 计算（sympy 回代）  L2 量纲（pint）  L3 边界（扰动/极限）
L4 条件一致            L5 建模与依据（仅人工）  L6 表达（仅辅助）
```

不是「一处笔误」——PDF 两处都反了（§05 表 + §08 线框）。理由是错误码、驳回原因、归因统计全按错误码表写，改表比改 PDF 便宜。
副作用一处：`checks[]`（步级自动检查）只到 **L1–L4**；`validation.failures[]` 允许 **L1–L6**，因为 E-01/E-15/E-21 的检测层本身就是 L5（人工）。

## 1. 屏一 · 单题诊断工作台

| 区 | 必须显示的字段（JSON path） | 显示规则 |
|---|---|---|
| 题干 | `question.stem_text`、`question.figures[].caption`、`figures[].caption_source`、`question.subquestions[].no/score` | caption 必须可逐条核对（D12）。`caption_source` 不显示给老师，只在 debug 层 |
| 结构化理解 | `situation.objects[].name/mass_symbol`、`given[].text`、`process_segments[].name/start/end`、`targets[].text`、`assumptions[]` | 四要素缺一就显式留空并标「未识别」，不许补白 |
| 解析主体 | `steps[].step_no`、`steps[].title`、`steps[].statement`、`steps[].equation.latex`、`steps[].law_ids`、`steps[].kind`、`steps[].value.number/exact/unit/direction` | 左列以**采分点号**（`point_id`）为主键，`step_no` 退为副标（D1：采分点即骨架）。`sympy` 不显示，但保留可复制 |
| 采分点账 | `grading.point_hits[].point_id/score_awarded/score_possible/hit/note`、`grading.missing_points[]`、`grading.extra_steps[]` | `hit=false` 的命中点用「部分分」样式；`missing_points` 单列一块，不混进步骤流 |
| 质检面板 | `validation.layers.L1…L4`（四格）、`validation.failures[].step_id/layer/error_code/detail`、`validation.zero_point_hit`、`validation.rewrite_rounds` | 步底色由该步 `checks[]` 里最高危层决定；`parse_status≠ok` 显示「解析降级」而不是「错误」；`zero_point_hit=true` 单独亮红条 |
| 本轮分档 | `triage.level`、`triage.reason`、`triage.signals.hard_check`、`triage.signals.self_rank` | `confidence` 只作排序角标，**界面上不许出现「N 分以上算通过」**（D4） |
| 裁决 | `review.verdict`、`review.rejected_steps[]`、`review.reason_codes[]`、`review.diffs[].before/after`、`review.added_steps[]`、`review.reordered` | 驳回必须选原因码才能提交（取值域 21 条错误码）；提交后 `diffs` 立即可见（D6） |

## 2. 屏二 · 异常队列

| 列 | 字段 | 说明 |
|---|---|---|
| 分档 | `triage.level` | 绿档不进队列，只 5% 抽样 |
| 题目 | `meta.question_id`、`meta.source`、`meta.question_no` | 与题库表联查，Schema 内不带题名 |
| 失败原因 | `validation.failures[0].layer` + `.error_code` | 多条失败时显示「首要失败层 + 条数」，如 `L1 · E-10（2 处）` |
| 轮次 | `validation.rewrite_rounds` | 三档路由靠「重写 2 轮仍失败」区分红档，必须显示 |
| 状态 | `review.verdict` | pending 才可指派 |

**缺口（Schema 给不了）**：方案线框里的「预计耗时」列没有数据源。原始设想是「层 × 题型 → 分钟数」的查表，这张表不在本 Schema 也不在采分点表里。D10 画线框时请留该列并标「待定口径」，别用分档直接映射成分钟数——那是编的。

## 3. 屏三 · 评测报告

| 指标 | 可从 Schema 算出？ | 算法 / 缺口 |
|---|---|---|
| 分值加权得分率（主指标） | 是 | `grading.weighted_rate`，**按 `meta.group` 分开报，禁止合并** |
| 采分点命中数 / 总数 | 部分 | 命中数 = `point_hits[].hit=true` 计数；总数 = `|point_hits| + |missing_points|`（依赖对齐完整，free 模式未对齐时会低报） |
| 红档比例 | 是 | `triage.level=red` 的题占比 |
| 一次通过率 | 是 | `level=green` 且 `rewrite_rounds=0` |
| degraded 比例 | 是 | `equation.parse_status=degraded` 步数 ÷ 总步数；**>20% 触发停用 L2**，报告上要显式写 |
| 分层（按过程数） | 是 | `len(situation.process_segments)`，1/2/≥3 三档 |
| 消融四组、扰动后稳定率、最终答案正确率 | **否** | 需要多配置跑批与金标答案比对，单条 answer 无法表达 |

## 4. 八个容易写错的字段（写代码前先读）

| 字段 | 约束 | 为什么 |
|---|---|---|
| `meta.mode` | `gold` / `free` / `rewrite` | `gold` 下 `point_id` 必填；`free` 由 S5 回填，可与 `step_id` 同形即报错；`rewrite` 只改失败步且 `rewrite_rounds≥1` |
| `equation.sympy` | 左边减右边 = 0，如 `f - mu*m*g` | 写成 `f = mu*m*g` 无法 `solve`；Schema 直接禁等号 |
| `equation.sympy` **写法** | **不许把单位算进数值系数**。写 `Rational(1,2)*acc*t**2`，不写 `2*t**2`（哪怕 acc=4 已算出）；保留物理量符号，让量纲跟着符号走 | 2026-11-25 裁定。`L - 2*t**2` 里的 2 其实是 ½·4（单位 m/s²），但 sympy 串里单位已丢失，L2 只能看到 `s²`，会把这个**正确**的式子判成 E-12。生成侧不守这条，L2 就会系统性冤枉「先算系数」的写法。兜底见 `验证器/units.py:DimUndecidable`（含整数系数时落 `na`） |
| `equation.parse_status` | `ok/degraded/failed` | 决定该步参不参与 L2 统计，**degraded 不计入 fail** |
| `equation.symbols[]` | T09 `symbol_id`，纯 ASCII | 禁 `v₀`、`v'`、`θ`、空格、中文；校验器会比对 sympy 里实际出现的符号 |
| `kind` | `judgment/equation/value/discussion/critical` | 对应采分点五类：①judgment ②equation ③value ④discussion（结果规范：单位/方向/有效数字/舍根）⑤critical。任务卡只列了 4 个值却声称对应五类，第 5 个值 `critical` 是本 Schema 补的，待你裁定用词 |
| `value.direction` | `+x/-x/+y/-y/逆时针/顺时针/null` | 自由文本方向无法比对 |
| `confidence` | 1–5 整数 | 只排序，不设阈值（D4） |
| `triage.level` | `green/yellow/red` | `zero_point_hit=true` 必 `red`，与分数无关 |

**拒收规则**：所有对象 `additionalProperties:false`。模型多吐一个字段就报错，不静默忽略——字段漂移是长 JSON 最先坏的地方。

> 符号白名单现存两处缺口（跑 A-06 实例时暴露，未擅自改 T09 的表）：
> ① 平抛时间无符号可挂，样例暂用 `t2`，建议 T09 补一行（`t2` = 第二段/飞行时间）；
> ② 板长白名单只有大写 `L`，采分点原文写小写 `l`，样例已归一为 `L`——归一化规则要写进 T09 说明，否则每道题都会来回换算。

## 5. 三处「Schema 给不了，界面别硬算」

1. **预计耗时**（队列排序用）：需要一张「失败层 × 题型 → 分钟」的经验表，不存在。
2. **金标答案比对**：Schema 只存解析，不存标准答案；「最终答案正确率」要另取采分点表/金标稿。
3. **扰动后稳定率**：需同题多样本，单条 answer 表达不了。
